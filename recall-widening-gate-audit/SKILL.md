# 召回外扩 + 二次检查排除：改筛选配置的安全流程

适用场景：一条**打分/筛选型**流水线（不是解析型——解析型见 `pipeline-parser-defect-postmortem`）。
用户说"关键词可以外扩，达到广泛搜索 + 二次检查排除的作用"、
"筛选太严了想放宽"、或你自己刚改了 keyword / 阈值 / 规则集，需要**证明没有误杀**。

## 0. 核心原则：召回与精度是两个独立的杠杆，别用一个换另一个

**错误做法**：放宽词表 → 噪声涌入 → 把阈值调高兜住。这会把真候选和噪声一起推下去。
**正确做法**：放宽词表（召回↑） + 对**歧义词**加共现门控（精度↑）。两者互不冲突。

## 1. 先分清"搜索"和"打分"两层（最容易漏改的一层）

| 层 | 作用 | 配置位置（举例） |
|---|---|---|
| **检索/抓取层** | 决定**抓多少**——这才是"广泛搜索" | 查询式列表（`crossref_queries` / `arxiv_queries`） |
| **打分/排序层** | 决定**如何排序与取舍** | 关键词组 + 权重 + 阈值 |

**只加打分词、不加检索式 ⇒ 抓取网并不会变宽**，你只是把同一批记录重新排序。
用户说"广泛搜索"时，**必须检查检索层有没有一起改**。

## 2. 改之前先量"前"（不可跳过的基线）

```bash
cp config/<profile>.json outputs/calibration/<date>_profile_after.json
git show HEAD:config/<profile>.json > outputs/calibration/<date>_profile_before.json
python tools/<calibrate>.py --profile ..._before.json --harvest <同一批> --today <date> \
    > outputs/calibration/<date>_before.txt
```

三个要点：
1. **"前"用 git HEAD 取**，不要凭记忆重写——否则 A/B 混入你自己的记忆误差。
2. **同一批输入**，只改一个变量（配置），否则归因不了。
3. 若该项目没有 `--profile` 开关，**先加上**（几行代码），让 A/B 可复现；
   输出里打印 `[from <path>]` 标注来源，防止拿错文件。

## 3. 设计"二次检查"门：锚点共现，不是负向词堆砌

**歧义词的噪声无法用无条件负向词解决。** 实测反例：
- 裸 `b-spline` 会捞进 CAD 曲面拟合、期权定价、神经网络逼近；
- 裸 `dft` 会捞进有机合成表征；
- 裸 `angular distribution` 会捞进解析数论；
- 裸 `schwinger` 会捞进 Dyson–Schwinger **点过程统计**、QFT 的 Schwinger 模型、磁星 Schwinger process。

这些词本身**是对的**，只在缺上下文时才是噪声。所以：

```jsonc
"context_anchors": ["photoionization", "photodetachment", "dyson orbital", ...],  // 无歧义主题词
"keyword_groups": [
  { "id": "competing_methods", "weight": 3, "requires_anchor": true, "terms": ["b-spline", ...] }
]
```

语义：`requires_anchor` 的组**须与任一锚点词共现**才计分；否则记入结果字段 `gated_groups`、贡献 0。
实现要点：
- 锚点匹配用**与词条相同的匹配器**（单词词界 + 短语子串），别另起一套正则。
- 结果 dict 同时回传 `gated_groups` 与 `anchor_hit`，否则后续审计无从下手。
- **不要门控核心组**：只给真正歧义的组加门；核心组被门控 = 自废主信号。
- **锚点列表非空是硬不变量**：有组被门控却没有锚点 ⇒ 静默全抑制。写进 profile 校验器。
- 加词**不加权重**：权重和不变，`max_score` 不变量才不受影响（"只扩召回、不动标定"）。

## 3b. 门控有三种粒度，选错粒度会白丢精度

| 粒度 | 配置 | 何时用 |
|---|---|---|
| 不门控 | 组在门控名单外 | 该组词条**全部**无歧义（核心组） |
| **组级门控** | `requires_anchor: true` | 该组**只有歧义词**能命中，或整组语义都需上下文 |
| **词级门控** | 组内 `gated_terms: [...]` | 组**整体精确**，只有个别词歧义（精确短语 + 少量泛词的混合组） |

词级门控语义：被列词**仅在锚点共现时**计分；若某组的命中**全部**来自 `gated_terms` 且无锚点，
该组不贡献（仍记 `gated_groups`）；组内其余词**完全不受影响**。

```jsonc
{ "id": "continuum_basis", "weight": 5,
  "gated_terms": ["spherical wave", "partial wave", "partial-wave", "stieltjes", "tchebycheff"],
  "terms": ["continuum state", "continuum orbital", "momentum-space", "stieltjes", ...] }
```

**判断法**：数一数该组"有多少词能独立命中噪声"。只有歧义词能命中 → 组级门控；
大部分是精确短语、少数是泛词 → 词级门控。
**别用组级门控处理词级问题**——那会连核心信号一起弃掉（自废主信号）。

**硬不变量**：`gated_terms` 的每个词必须**也在该组 `terms` 里**，否则永不生效且**静默**。
必须写进 profile 校验器（"声明了门控却没在词表里"是零信号陷阱）。

## 4. ★ 强制：审计**被抑制项**，不能只审计新增项

这是本流程的核心纪律。**只看"新增了什么"等于没验证**——你根本不知道门吞掉了什么。

审计必须回答两个问题，缺一不可：
1. 被抑制的记录里，**有多少其实在范围内**？→ 期望 **0**。
2. 分数下降的记录里，**有多少其实在范围内**？→ 期望 **0**。

```bash
python tools/audit_anchor_gate.py --harvest <harvests> --diff-profile <before>.json
# 期望输出末尾：
#   => every suppressed hit is noise; the gate is safe for this corpus.
#   => no in-scope record lost score; every decrease came from noise suppression.
# 退出码非 0 = 有真记录被丢 → 补锚点措辞或撤掉门控
```

把它做成**门禁**（非零退出即失败），并纳入月度评审清单。
审计输出要**给出噪声簇的实名样本**（不只数字）——只有念得出名字才能判断它真是噪声。

**注**：若流水线的运行日志只写精简字段（不含 `gated_groups`），门控统计**只能**从
校准/审计工具取，**不要**试图从运行日志里统计——那里恒为 0，会让你误判"门没生效"。

## 5. 证明新测试非空转（否则回归测试是装饰）

对**门控本身**做变异测试，至少五刀：
- `if group.get("requires_anchor") and not anchor_hit:` → `if False:`（组级门失效）
- `anchor_hit = any(...)` → `anchor_hit = True`（永不需要锚点）
- `anchors = profile.get("context_anchors") or []` → `anchors = []`（全抑制）
- `if not anchor_hit and group.get("gated_terms"):` → `if False:`（词级门失效）
- 词级过滤 `hits = kept` → `hits = hits_original`（词级门被绕过，仍计分）

再加 profile 侧变异：清空锚点列表、把**研究类型**塞进排除列表、清空排除列表。
每刀都要断言指定测试**变红**，且源码 sha256 复原一致。

**测试数据要避开锚点词**：写"核心组不受门控影响"的用例时，标题若含锚点词（如
`continuum orbital`）会让 `anchor_hit=True`，门自动放行 → 用例**假通过**。
构造"应被门控"的用例须确保文本里**没有任何锚点词**。

## 6. 外扩会放大抓取限流：可靠性是外扩的隐藏成本

**查询数变多 ⇒ 单位时间请求变密 ⇒ 限流/超时概率上升。** 实测：16 个检索式 @1.5s
间隔下有 **7 个静默 SSL 握手超时**（同一批 @5s 全部成功）；单查询探针甚至 >120s。
一次"外扩后抓取量只涨了 10%"的观察，很可能不是"网上没东西"，而是**1/3 的查询被丢了**。

必须做三件事：
1. **抓取函数内置失败重试**：失败标签延迟 `max(3 × 基础间隔, 5s)` 重试一次，
   仍失败者记入**审计字段**（如 `crossref_failed_after_retry`），并打印 `[N/M queries OK]` + `STILL FAILING`。
2. **把"覆盖查询数 == 配置查询数"当硬门禁**。`errors` 非空且占比大时**不得进入下游打分**——
   那等于用缩水的输入报告"没有新东西"，是**假阴性**，比假阳性更隐蔽。
3. **补抓而非重跑**：用 `--only <失败标签> --sleep 5` 只补失败的那几个，产出第二个 harvest，
   与第一个**一并**送入下游（二者查询集合不重叠，不会重复计数）。

## 7. 诚实报告边界

**外扩很可能不改变纳入量**。本项目实测：词 90→143、查询 10→16，抓取量 +59%，
但 `medium` 档前后**都是 0**——买到的是排序与精度，不是产能。
若根因是"上游检索本身召回不到"（如词袋检索精度仅 7%），改 profile **治不了**。
务必把这一句写进报告，否则会造成"改了配置就该有产出"的错误预期。

## 8. 坑（都踩过）

- **同一文件并行发多个 Edit ⇒ 静默丢失更新**：一次消息里发两个 Edit，只有后一个落盘，
  **两个都返回 success**。实测丢失了一处 `requires_anchor: true`，靠下游脚本打印
  "应有 6 组门控、实际 5 组"才暴露。**改同一文件必须串行；改完必须 grep 复核每个目标字段。**
- **门控粒度选错**：对"精确短语 + 少量泛词"的混合组用组级门控，会连核心信号一起弃掉（见 §3b）。
- **`gated_terms` 写了不存在的词**：静默不生效，表现为"门没起作用"（见 §3b 硬不变量）。
- **用缩水 harvest 报"无新增"**：外扩后限流丢查询，触发假阴性（见 §6）。
- **只看抓取量涨没涨、不看覆盖查询数**：前者可能因单查询返回上限而虚高（见 §6）。
- **挖掘工具的"参照集"会被污染**：用正则挑"已知在范围"的样本来当召回标尺时，
  若把歧义词（如裸 `b-spline`）写进参照集，参照集本身就是噪声，
  于是**每个"漏检"都是假的**。参照集只用无歧义词；存疑宁可不要；
  **跑完先打印参照集人工看一眼**再信它的结论。
- **只加词不加查询**（见 §1）。
- **阈值兜底代替门控**（见 §0）。
- 只审计新增、不审计抑制（见 §4）。

## 9. 收尾清单

```text
1. profile 校验器通过（含"有门控必须有锚点""gated_terms ⊆ terms"）
2. 单元测试全绿 + 变异测试 N/N（含词级门控两刀）
3. 抑制审计退出码 = 0（0 条误杀）
4. 受保护文件（受控事实来源）零 diff
5. dry-run 仍产出与预期一致（无假纳入）
6. 抓取覆盖查询数 == 配置查询数；失败后补抓字段为空
7. 前后校准表写入项目规范，注明"买了什么、没买什么"
8. grep 复核每个目标字段真的落盘了
```

**"实测"与"重放"的分工**：配置改动可以用历史数据离线重放验证（A/B + 审计），
但**抓取层的缺陷只有真跑才会暴露**（限流、超时、返回上限、时间戳语义）。
改了检索层之后，**必须真跑一次**再宣布完成；离线全绿不等于线上可用。
