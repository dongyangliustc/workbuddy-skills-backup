# docx Toolkit — 精细结构化操作

处理 docx 的**结构性缺陷修复**与**精细定位审计**。常规读写、格式排版不在此范围。

## 边界（重要）

| 需求 | 应使用的工具 |
|---|---|
| 常规 docx 读写、格式排版、内容生成 | `tencent-docx` / `tencent-local-office-edit`（插件） |
| 公式图片 → 原生 OMML、字体缺字形、批注审计、附图重绘 | **本技能** |

## 场景路由

| 症状 / 需求 | 读取的 reference |
|---|---|
| Word 里符号显示为方块/问号（如 ⁻ ₂ − ⑪⑫⑬、单个上标或希腊字母） | `references/glyph-fix.md` |
| 文档内公式/符号以 PNG 图片嵌入，或出现无法渲染的 `\(...\)` LaTeX 残留 | `references/omath-latex.md` |
| "帮我审 XXX.docx 的 P14 L248-272""看一下我的三个批注" | `references/locate-and-comment.md` |
| 需要正文 ↔ SI 补充图表编号的引用覆盖核对 | `references/locate-and-comment.md` |
| 交底书/专利文档重绘示意图（系统框图、流程图）并同步修订 docx | `references/fig-revision.md` |

## 五条通用铁律

1. **先查 schema，再调 editor_sdk。** 不要凭记忆拼参数。
2. **勿信转换稿的文字**。`doc_find` 确认 docx 实际文字后再做替换。
3. **另存时间戳新稿，保留原稿**。不要覆盖修订来源。
4. **程序化校验先于目检**。能脚本断言的重叠/溢出/编号覆盖，不要靠眼睛多轮循环。
5. **抽正文：按 `</w:p>` 切块后只取 `w:t`。** 禁用 `<w:p[ >].*?</w:p>` 配 `<w:t[^>]*>(.*?)</w:t>` ——
   `<w:t` 会同时命中 `<w:tbl` / `<w:tc` / `<w:tr` / `<w:tab`，导致段落数与字符数被**严重低估**
   （实测：错误写法得 206 段 / 1 915 字符、**全部关键词计数为 0**；正解得 207 块 / 46 289 字符）。
   同理**不要在原始 XML 上做子串搜索**：Word 常把一句话切成多个 `w:t` run（域码、上下标、拼写修订），
   未重组的 `equivalent forms` 计数会假报 0。

## 环境须知（Windows 沙箱，已实测）

- **ASCII 路径优先**：`doc_to_image` 常因非 ASCII 路径或外部 API 失败，勿依赖它做核验；改用 zip 层核验（见 `references/fig-revision.md`）。
- **editor_sdk 会话中断后 pool 清空，未保存编辑全部丢失**：每完成一组修改立即 `save_file` 落盘。
- **并行修订线**：交底书等目录常存在时间戳文件名的并行产物，动手前 `ls -la` 确认最新版本与线归属。
- **改动核对（"上轮之后他改了什么"）**：先 `md5 + mtime` 判是否变；变了再拿**上一版导出文本**与现版导出文本跑
  `difflib.unified_diff`。两条硬约束：① **只认散文段落的 diff** —— 表格、显示公式、空行的 diff 多半是伪改动；
  ② **双方导出器必须同构** —— 若旧导出跳过表格与公式，则所有表格/公式差异一律作废。
  核对成品应固定成一份 md：指纹表 + 复现命令 + 逐条判定 + 伪改动排除清单 + 我方标记锚点的现状表。
