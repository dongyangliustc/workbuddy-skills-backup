# 文献 PDF → 指定图 → 裁图 → 取数（含图例）（S1 + S2）

本文档记录 `chartdigit/pdf.py`（**定位与裁剪**）与 `chartdigit/legend.py`（**图例提取与颜色校验**）的原理、阈值依据，以及开发过程中实测暴露的失败模式及修正。§1–§9 为 S1（定位与裁剪），§10–§15 为 S2（图例、颜色校验、排除掩码）。

> 适用范围：吃一份文献 PDF，回答"第 N 张图在哪一页的哪个矩形里"，按 600 dpi **局部渲染**出 PNG，再可选地**从图例读出曲线名称与精确颜色**并经程序化校验后用于配色。
> 不适用：图例文字 OCR（`tesseract` 未安装，亦不引入任何新依赖）、图片输入（走既有 `extract` 流程）。

---

## 1. 为什么必须"渲染页面再裁剪"

**现代期刊插图是矢量图**。实测：`Communications Chemistry, 4(1), 72.pdf` 第 5 页有 **9728 个矢量绘图对象、仅 11 个位图**。所以 `page.get_images()` 拿不到插图内容——它只给你整页扫描件那类位图。

唯一稳妥的路径是 **`page.get_pixmap(dpi=, clip=rect)`**：把指定矩形按指定 dpi 光栅化。

**必须用 `clip=`**，否则成本失控：

| 口径 | 体积 | 说明 |
|------|------|------|
| 整页 600 dpi | 97–104 MB | 不可能作为中间产物 |
| `clip=` 裁剪后 | 6.5–14.7 MB | 实测单栏图 |
| 本技能夹具 Fig.3（600 dpi，1753×1207 px） | 约 1.0 MB | 见 `tests/figures/caseP1_paper.pdf` |

输出固定 **PNG（无损）**，不输出 JPEG——JPEG 的抗锯齿会让后续"按图例精确 RGB 取色"失效。

## 2. 三通道定位（逐页判定，A → B → C）

| 通道 | 原理 | 实测命中 |
|------|------|---------|
| **A 图注锚定** | 文本层**行级** bbox 匹配 `Fig./Figure/Table N`，图形区域 = 该图注**同栏上方** | P2 ✓ P3 ✓ **P1 ✗** |
| **B 位图 bbox** | `get_text("dict")` 中 `type==1` 的 block bbox | **P1 ✓**（老刊扫描页）P3 ✗ |
| **C 矢量簇** | `get_drawings()` 的 rect 按纵向空隙聚类，取面积最大簇 | 兜底（近乎空白页） |

优先级 **A → B → C**，且**逐页**判定：某页 A 有候选就不再启用 B/C。这条"逐页"很关键——同一份文献里既有矢量图页也有扫描图页（P1 全扫描、P3 全矢量），按文档级统一选通道必然错一半。

实测（`from-pdf --list`，2026-09-17）：

| 文献 | 候选数 | 通道构成 |
|------|-------|---------|
| P1 Obara-1986 | 4 | 全部 `raster`（0.60） |
| P2 J. Phys. Chem. A 2007 | 4 | 全部 `caption`（0.95），另识别 2 处表注（不裁） |
| P3 Commun. Chem. 4(1) 72 | 14 | 10 `caption`（0.90）+ 4 `vector-cluster`（0.40） |

### 2.1 通道 A 的两个必要收窄

**(a) 位图 bbox 要与文字 bbox 同源。** `page.get_text("dict")` 在同一坐标系里同时给出文字与图像的 bbox，无需另调 `get_image_info()`。

**(b) 通道 B 要滤掉两类"非插图"。**

| 滤除对象 | 阈值 | 实测依据 |
|---------|------|---------|
| 公式 / 图标级小图元 | 任一边 < `MIN_RASTER_PT = 40` pt | 夹具 `caseP1_fallback.pdf` 第 1 页放了 5×5 pt 的位图 |
| **整页扫描位图** | 面积 ≥ `MAX_PAGE_RASTER_FRAC = 0.9` × 页面积 | P1 每页都有 `(0,0,576,810)` 的 2400×3375 整页图；它不是插图 |

### 2.2 通道 C 的聚类

`find_vector_cluster`：按 y 排序后贪心合并，**纵向空隙 > `VECTOR_GAP_PT = 20` pt 即断开**，取面积最大的簇。

贪心而非两两比对，是因为现代期刊单页矢量对象数可达 2883–9728，O(n²) 不可接受。
置信度**封顶 0.40**——"这里有一坨矢量图元"离"这是哪张图"还有很远。

## 3. 图注正则与消歧门（**这是本层唯一会静默出错的地方**）

### 3.1 正则

```
^\s*(?P<kw>Fig(?:ure)?\.?|TABLE|Table|表)\s*(?P<num>\d{1,3})(?P<panel>[a-zA-Z])?
(?=[\s.:|;；,，、)\t]|$)
```

三处细节都有实测依据：

1. **`(panel)` 之后不允许空白**。`Fig. 2 TPES and TPEPICO…` 里 `T` 紧跟在空格后，早期写法把 `T` 吃成了面板字母，标签变成 `2T`。加 `\s*` 就会踩这个坑——所以 `\s*` 只在 `num` 与 `kw` 之间。
2. **末尾零宽前瞻**锁定标签词边界。目的是让 `Table 1); (iii) …`（P3 实测的正文误匹配）**仍然被识别出来**，从而进入消歧门被拒——而不是在正则层悄悄漏过、让人以为"没有这一条"。
3. **编号与面板字母一律走具名分组**（`group("num")` / `group("panel")`），不用 `group(1)`。开发期实测：加了一个 `kw` 分组后，位置索引整体错位，编号被读成关键词本身，标签变成 `"Figure1"`——而各标签**互不相同**，所以不报错、不歧义，一路静默错到底。

### 3.2 为什么必须有消歧门（P2 实测踩中）

P2 正文里有一句：

```
Figure 3 for a particular set of fit parameters. The analysis of…
```

它是**正文**，不是图注，但以 `Figure 3` 起头，正则必然命中。若直接采信，`--figure 3` 会裁出一块正文。

消歧门 `caption_decision` 三门串联，返回 `(结论, 生效分支)`：

**G1 段落结构** —— 真图注自成一段，故匹配行必须是所在 block 的**首行**；仅当 block 本身 ≤2 行时放宽（孤立短块）。

> 实测：P2 第 2 页那句是 **13 行 block 的第 8 行** → 直接被 G1 拦下。
> 注意区分两种不同的拦截层：`Figure 6(a) and (b) shows…` 因标签后紧跟 `(`（不在前瞻字符集内）**在正则层就不命中**，连消歧门都进不去；而上面那句是**能过正则、必须靠 G1 拦**。两者都该被挡住，但走的是不同关卡。

**G2 字号或显式格式** —— 满足任一条即接受：

| 分支 | 条件 | 覆盖的实测情形 |
|------|------|---------------|
| `size` | `size < body_size − SIZE_EPS`（`SIZE_EPS = 0.25`） | P3 图注 8.0 / 正文 9.5；P2 图注 8.5 / 正文 9.5。**最强信号** |
| `separator` | 标签后紧跟 `.`/`\|`/`:`/制表/两个以上空格 **且** block 行数 ≤ `SEP_MAX_BLOCK_LINES = 4` | P2 第 3 页 `TABLE 1: Valence Band Energies…`——该页表格正文 8.5 pt 反而**比 9.0 pt 的表注小**，单靠字号会漏 |
| `single-line` | 该行是**孤立单行 block** 且长度 ≤ `SINGLE_LINE_MAX_CHARS = 200` | "图注与正文同字号同排版、且无分隔符"的期刊 |

`body_size` 由 `page_body_size()` 给出：**按字符数加权**取该页出现最多的字号（不是按行数——长正文段必须主导统计）。`size < 4.0` 的装饰性小字（页眉页码）不计入基准。

`single-line` 分支是**故意放宽召回**的：本层按"绝不猜"的红线**宁多勿漏**——多出的候选只会变成 `--list` 里一条用户可见、可消歧的记录，而漏检会让通道 A **静默失去整张图**。

### 3.3 标签命名空间（对 SPEC 示例的一处必要收窄）

SPEC §3.1.1 的示例把 `label` 写成裸数字。本实现把**表注**放进 `T` 命名空间：图注 `"3"` / `"3a"`，表注 `"T1"` / `"T2"`。

理由是真碰撞：P2 里 `Figure 1` 与 `TABLE 1` 同号、`Figure 2` 与 `TABLE 2` 同号。若都用裸数字，`--figure 1` 会把**一张图与一张表**报成"歧义"，而二者本无歧义。分开命名空间后，`--figure 1` 唯一指向那张图。

**表注被识别但不产出候选**：本阶段的图形区域算法是"图注**上方**同栏"，而表注在三类实测文献里都是"标题在上、表格在下"；且 P2 第 4 页的表格是**横向旋转页**（正文块横跨 x 36.5–744，而表注块只有 x 36.5–322.6），按表注 block 推栏宽会截掉大半张表。

> 与其给出一张**看似可信的错表**，不如明确不裁。表注一律经 `diagnostics` 的 `channel == "table-caption"` 回报给调用方。

## 4. 图形区域：同栏 + 图注上方

`coarse_rect_for_caption` 给出**粗定**矩形：

- **纵向**：下界 = 图注**行**顶边（不是 block 顶边，也不含图注自身）；上界 = 同栏内向上最近的一个**正文段落** block 的底边；不存在则取页眉/页边距。
- **横向**：取栏范围。

### 4.1 栏范围不能只看图注 block

单行图注的文字宽度往往**远窄于栏宽**：P3 的 `Fig. 7 Type I conformer (C+D) bfþ1g` block 只有 `43.6–168.1`，而该栏实为 `43.6–291.7`。

早期版本用"窄就退回整幅正文宽"兜底 → 同一页的 Fig.7 与 Fig.8 **都**被判成全页宽、区域互相覆盖。现改为**按栏切分**（`column_bounds`）：

1. 取正文 x 范围 `(tx0, tx1)`；
2. `find_column_gutter` 检测栏间空带中心 `g`；
3. 图注 block 横向已接近整幅正文宽（`x1 ≥ tx1 − 0.15·W` **且** `x0 ≤ tx0 + 0.15·W`）→ 整幅宽；
4. 否则按图注中心落在 `g` 左/右决定取左栏 `(tx0, g)` 或右栏 `(g, tx1)`；
5. 单栏页（无空带）→ 整幅宽。

第 3 步**必须同时看左右两边**。开发期实测的失效：只看右边，于是 P3 第 6 页 Fig.10 与第 5 页 Fig.3 的图注 block 右边界恰为 551.7（= 正文右缘）→ 两张**右栏**图被裁成了整页宽。

### 4.2 栏间空带检测的两个坑

`find_column_gutter` 把文字 block 的 x 区间投影到 x 轴，找最宽的连续空白段；中心落在正文宽度中间 50% 且宽度 ≥ 8 pt 才判为双栏。

**坑 1：跨幅 block 必须剔除。** P3 页眉 `43.6–551.7` 横跨整幅正文宽，留在 profile 里会把整条 x 轴填满、空带消失 → 双栏页被判成单栏。所以只用宽度 < `0.80 ×` 正文宽的 block 建 profile。

**坑 2：上界不能只认"图注上方最近的文字 block"。** 按字面执行会取到**图内**的刻度标签或面板标签。实测 P3 第 5 页 Fig.2 上方最近的非图注文字是图内刻度标签 `"11"`（y1 = 368.5）与面板标签（`m/z 70` 等），字面执行会裁出一条 8 pt 的缝。

修正：加 `_is_paragraph` 过滤，要求 block **≥2 行** 且**贴栏左缘**（左边界落在栏左界 `+ 10%` 栏宽 内）且右边界覆盖栏宽 ≥ `85%`。

> 右边界判据用**比例**而非等容差，是因为正文是**左对齐、右边参差**的——等容差会把真实正文段全部误杀。而图内标签（如 P3 Fig.5a 的 x0 = 76.1，距栏左界内缩 32 pt）会被稳定排除。

## 5. 先粗定后收紧

粗定矩形必然含留白、甚至邻图，故一律收紧一次（`tighten_rect`）：

1. 按 `TIGHTEN_DPI = 100` 渲染粗定区（成本可忽略）；
2. 在渲染图上找**非背景行/列**（`content_bounds`）：背景 = 该区域**众数色**，256 级灰度差 < `BG_TOL = 8` 视为背景；
3. 换算回 PDF 点坐标。

### 5.1 行方向：只从"最靠近图注的底部内容带"起向上吞并

`GAP_PT = 18` pt 的桥接空隙。依据：P3 第 5 页 Fig.2 图**内**最大空隙是 12.9 pt（三条堆叠面板之间），取 18 pt 留约 40% 余量；而两张不同图之间通常 ≥ 20–30 pt。这样同栏上方若还有另一张图或一段正文，不会被卷进来。

### 5.2 列方向：**必须先按行带裁剪再统计**

否则粗定区内任何别处的文字都会把 x 范围撑开。开发期实测：夹具里 Fig.5a 的 x0 被同一栏中**上一张图的图注**从 70 拉到 50.7。

### 5.3 收紧同时充当校验

| 判据 | 阈值 | 处置 |
|------|------|------|
| 长宽比 | `h/w < MIN_ASPECT(0.15)` 或 `> MAX_ASPECT(8.0)` | 丢弃候选 |
| 面积 | `< MIN_AREA_FRAC(0.01)` × 页面积 | 丢弃候选 |
| 粗定退化 | 宽或高 ≤ 1 pt | 丢弃 |
| 无内容 | `content_bounds` 返回 None | 丢弃 |

丢弃一律**降低 confidence 并在 diagnostics 里写明 reject 原因**——宁可报"定位失败 + 手工框选指引"，也不猜。

## 6. 颜色与坐标换算（S2 的前置固化）

`hex_color(rgb)`：RGB 浮点 → `#rrggbb`，量化规则是 **`int(v*255 + 0.5)`**（`.5` 进位），越界先钳到 `[0,1]`。

| 输入 | 输出 | 说明 |
|------|------|------|
| `(0.5, 0.5, 1.0)` | `#8080ff` | `.5` 进位 |
| `127/255 = 0.498` | `7f` | `127.49 → 127`。**P3 图例色块矢量对象给出的正是 `#7f7fff`**——源图的 8 bit 值 `0x7f` 存进 PDF 后是 0.498 |

把舍入规则**钉死在函数里**而不是散落各处，是让 `#7f7fff` / `#8080ff` 两种写法都能被判为同一色的前提。

`pt_to_px` / `px_to_pt` / `box_pt_to_px`：PDF 点 ↔ 裁剪图像素（原点在 `rect_pt` 左上角），换算因子 `dpi/72`。S2 的**排除掩码**（把 PDF 文本 bbox 变成裁图上的屏蔽区）即用 `box_pt_to_px`，故本阶段先行固化并单测。

## 7. CLI 口径（`from-pdf`）

```bash
PY=".../python.exe"; SKILL=".../chart-digitizer"

# 1. 列出候选（无副作用、不写文件、永远退出码 0，除非 PDF 打不开）
"$PY" "$SKILL/scripts/chartdigit.py" from-pdf paper.pdf --list

# 2. 裁出指定图（默认 600 dpi；下限 300）
"$PY" "$SKILL/scripts/chartdigit.py" from-pdf paper.pdf --figure 3 -o fig3 --dpi 600

# 3. 歧义/定位失败时：手工框选（--page 1 起，同 PDF 阅读器显示的页码）
"$PY" "$SKILL/scripts/chartdigit.py" from-pdf paper.pdf --page 5 --rect 43.6,130,266.5,372 -o fig3
```

退出码沿用既有约定：**0** 成功 / **1** 用法与定位问题 / **2** 提取失败 / **3** 无 GetData / **4** 待人工审核。

**行为约定**

- `--list` 是人机消歧的**主入口**，必须随时可跑、不留痕。
- `--figure N` 遇 `ambiguous_with > 1` → **退出码 1**，stderr 打印**全部**候选（页码 + bbox + 图注首行）并给出可直接复制的 `--page ... --rect ...`。
- 定位失败 → **退出码 1**，打印 `--list` 结果与手工框选指引，**不得**猜。
- 裁剪成功后 **stdout 直接给出下一步 `extract` 命令**，使 `from-pdf → extract` 可串成一条链。
- 三个选择器（`--list` / `--figure` / `--page`+`--rect`）**互斥**，多于一个即退出码 1。

## 8. 溯源 sidecar

裁剪时在 PNG 旁写出同名 `.json`：

```json
{
  "pdf": "...", "page_no": 4, "rect_pt": [...], "dpi": 600,
  "px_size": [1999, 2641], "source": "caption", "caption": "Fig. 2 TPES and ...",
  "confidence": 0.9, "label": "2", "generated_at": "..."
}
```

这是"报告必须可独立复核"这一既有约定的延续：任何人拿到 PNG 都能反查它是从哪份 PDF 的哪一页哪个矩形、以什么 dpi 渲染出来的，以及当时的置信度与图注原文。

`from-pdf --list` 会把 `rect_pt` 精确到 0.01 pt 打印出来，**可直接复制**进下一次 `--rect`——这是人机消歧闭环的最后一环。

# S2 · 图例提取、颜色校验与排除掩码

## 10. 图例几何签名（`group_legend_lines` / `pick_legend_group`）

图例在版面上的可辨特征不是"图例"这个词，而是**四条几何条件的交集**。四条**必须同时满足**才成组，缺一条就会开始吞掉轴标题或面板标签：

| 条件 | 常量 | P3 实测 |
|------|------|---------|
| 字号 < 区域内最大字号的 0.80 | `LEGEND_SIZE_RATIO = 0.80` | 图例 6.64 pt vs 轴标题 9.5 pt → 比值 **0.69** ✓ |
| 组内左边界 x 极差 ≤ 3 pt | `LEGEND_ALIGN_TOL_PT = 3.0` | 三条均为 `x = 87.27`，极差 **0** ✓ |
| 行距 < 1.6 × 行高（top→top） | `LEGEND_SPACING_RATIO = 1.6` | 行推进 6.71 pt、字号 6.64 → **1.015** ✓ |
| 条目数 ≥ 2 | `LEGEND_MIN_ITEMS = 2` | 3 条 ✓ |

第 4 条的作用是**排除孤立的轴标签**：单个小字号文字（如 `m/z 70`）无法与图例区分，必须有 ≥2 条**左对齐共线**的才成组。

行距用 **top→top** 而非"间隙"：PDF 文本层的行 bbox 高度随字形（有无降部字符）浮动，用间隙会随字符串内容抖动。

`pick_legend_group` 取**条目最多**的组；并列时取**最靠上**的组（图例通常在图内右上角，而重复的坐标轴标签簇在下）。

## 11. 色块关联与取色（`geo_candidates` / `pick_swatch`）

### 11.1 几何候选集

对每条图例文字，在**同页矢量对象**里筛出候选色块：

| 判据 | 常量 | 说明 |
|------|------|------|
| y 区间落在文字行内（上下各放宽 3 pt） | `SWATCH_Y_SLACK_PT = 3.0` | 文字 bbox 与实际色块的中线常有小偏差 |
| 右端不越过文字左边界（放宽 0.5 pt） | `SWATCH_X_SLACK_PT = 0.5` | "在文字左侧" |
| 宽度 > 3 pt | `SWATCH_MIN_WIDTH_PT = 3.0` | 滤掉零宽线段与点状图元 |
| 面积 > 1 pt² | `SWATCH_MIN_AREA_PT2 = 1.0` | 滤掉亚像素碎片 |
| **右端距文字左边界 ≤ 12 pt** | `SWATCH_MAX_GAP_PT = 12.0` | **SPEC 字面判据之外的加固**，见下 |

`SWATCH_MAX_GAP_PT` 是 S2 实测后加的**第五个**条件。SPEC §3.2.2 只要求"在文字左侧"，但真实期刊里曲线被拆成大量小线段，某一小段完全可能同时满足"在文字左侧""宽度 > 3""y 落在文字行内"——而**R1 校验抓不住它**（该颜色在图内当然大量存在），于是会静默地把曲线段的颜色当成图例色。P3 实测色块 `x ∈ [78.99, 83.68]`、文字 `x = 87.27` → 空隙仅 **3.4 pt**；取 12 pt 留约 3.5 倍余量。

该常量在 `pick_swatch(max_gap=...)` 上开放，使单元测试可以**关掉距离加固**、从而证明"近黑判据本身"也足以挡住刻度短线——否则无法排除"只是靠距离顺带挡住"的可能。

### 11.2 取色优先级：描边 > 填充中彩度最高者（芯色）

```
kept = [d for d in geo_candidates if not is_neutral(d)]
若 kept 中存在 type 含 "s"（描边）者 → 取其中 x1 最大者的 color
否则 → 取 fill 中 (彩度, x1) 最大者的 fill
```

两处细节：

**(a) `fs` 按描边处理。** PyMuPDF 的 `type` 取 `f` / `s` / `fs`；SPEC 说"优先描边色，因为是线段样本的真实颜色"——该语义对 `fs` 同样成立，故判据写作 `"s" in type`。

**(b) 嵌套色块取芯色。** 同一 y 区间出现多个 fill 时，**内层才是芯色**：P3 实测外层 `#7fe57f`、内层 `#3fd83f`，内层饱和度高。故按 `(彩度, x1)` 降序取第一个，而不是按面积或按文档顺序。

**(c) 多重描边取 `x1` 最大者**（离文字最近）：远处的残段更可能是曲线。

**(d) 近灰/近黑一律跳过。** `is_neutral` 判据 `(max(rgb) - min(rgb)) × 255 < NEUTRAL_CHROMA(25)`。P3 实测混进几何候选集的是 `#000000`、5×0.5 pt 横向短划，彩度 0。夹具里 4 条近黑刻度短线**确实落进候选集 ≥2 处**（测试断言了这一点），一旦不排除就会被当色块。

### 11.3 `kind_hint`（图元类型提示，仅作参考不作强制）

| 判据 | 值 | 常量 |
|------|-----|------|
| 右端存在垂直短划（横线 + 端点竖线 = 误差棒标准画法） | `errorbar` | `KIND_TICK_ASPECT = 2.0`、`KIND_TICK_BACK_PT/FWD_PT` |
| `w/h > 3` | `line` | `KIND_LINE_ASPECT = 3.0` |
| `1/3 < w/h < 3` | `marker` | `KIND_MARKER_ASPECT = 1/3` |
| 其余（`w/h ≤ 1/3`，竖长条） | `errorbar` | 本实现补齐的空档 |

SPEC 只给了前三条。末条是补齐：竖长条色块最合理的解释就是误差棒，而 `kind_hint` 不强制，猜错的代价仅是一个提示值。

## 12. R1 颜色一致性校验（`verify_legend_colors`）——**本方案唯一会静默出错的地方**

### 12.1 为什么必须做

若期刊对图例色块做了**淡化 / 换色 / 加边框**，按图例颜色去 `extract_series(colors=...)` 会**一条曲线都提不到**，或提到错误对象——**而产物看上去完全正常**。这类错误没有任何下游信号能发现，必须在源头程序化校验。

### 12.2 三态语义

对每个图例颜色，在**图形区域内**统计与它距离 `< tol` 的像素数（**复用 `extract.color_mask` 的距离函数，不另写一套**）：

* 全部命中且均 ≥ `min_pixels` → `ok=True`
* 任一命中数为 0 或 < `min_pixels` → `ok=False`，`missing` 点名该色
* 命中数与图例条目数不匹配 → `ok=False`

阈值：`VERIFY_TOL = 64.0`（与 `color_mask` 默认 tol 一致）、`VERIFY_MIN_PIXELS = 30`。

### 12.3 加固项：剔除图例色块后再统计（`plot_hits`）

**色块本身就在图形区域内**。夹具色块 5×2.5 pt 在 600 dpi 下约 880 px，远大于 `min_pixels = 30`——只用区域总命中数，校验会被色块自己"喂饱"而**形同虚设**。

故加第二条：给定 `swatch_boxes` 时额外统计**剔除色块后**的命中数 `plot_hits`。两个条件同时满足才 `ok=True`。这一条才真正回答"这个颜色在**曲线区**里存在吗"。

夹具 Fig.3 是该加固的**反证用例**：

| 条目 | 区域命中 `hits` | 剔除色块后 `plot_hits` | 结论 |
|------|----------------|----------------------|------|
| `TD 493 K` `#3fd83f` | **882** px（≥ 30，单看这条会通过） | **0** px | 失败 |

### 12.4 `matched` 的口径（S2 收工前修正的一处自相矛盾）

`matched` 必须**同时**计入 `missing` 与 `plot_missing` 两类失败：

```python
bad = set(missing) | set(plot_missing)
matched = n - len(bad)
```

只用 `missing` 会漏掉"区域总命中够、但剔除色块后不足"这一整类，报告随即出现 `checked=3 matched=3 ok=False` 这种**自相矛盾**的组合——而 `matched` 恰是人快速扫报告时**唯一的数量信号**，矛盾直接摧毁可发现性。夹具 Fig.3 正是这一情形（修正前 `matched=3`，修正后 `matched=2`）。

### 12.5 失败一律回退，绝不硬用

校验失败时 `LegendInfo.usable == False`，`cli.resolve_legend_wiring` 回退 `dominant_colors` 自动配色，并把对照写进交付物：

```
图例颜色校验未通过，已回退自动配色。
  原因：剔除图例色块后仍找不到（或命中不足）：#3fd83f
  命中像素（区域内）：[15400, 882, 16905]  阈值 min_pixels=30
  命中像素（剔除图例色块后）：[14520, 0, 16044]
  图例给出的颜色：TD 415 K=#7f7fff、TD 493 K=#3fd83f、RH=#ff7f7f
  图内实际主色：…
```

`fallback_message` 同时给出**图例给出的颜色**与**图内实际主色**，便于人工判断是"期刊换色"还是"本工具关联错了色块"。

> **踩过的坑**：`region_colors` 是 **8 bit 整数**口径（与 `extract.dominant_colors` 一致），**不能**用 `pdf.hex_color` 渲染——那个函数的入参是 0..1 浮点，喂 8 bit 整数会被钳到 1.0，六个颜色全变 `#ffffff`，报告随即失去全部诊断价值。改为手动 `"#%02x%02x%02x" % tuple(int(v) & 0xFF for v in c[:3])`。
>
> 另一个坑：`region_colors` 必须喂 `drop_antialias_colors` **之后**的有效候选，否则首位的"主色"是轴线/光晕的近黑，同样失去诊断价值。

### 12.6 命名规则：名称与 hex 始终并存

`legend_series_name` → `"TD 415 K #7f7fff"`。

理由：`c1_d93637` 一看便知是占位符；错命名为 `TD 415 K` 则**看起来可信**。保留 hex 使错误命名可被发现、可被核对。名称先做空白规整（`" ".join(name.split())`），否则 PDF 文本层的首尾空格会在交付物里拼出双空格，使序列名无法稳定比对。

## 13. 排除掩码（`text_box_to_px` / `exclude_boxes_px` / `apply_exclude_mask`）

把图内全部文字行的 bbox 换算成裁剪图像素矩形，供 `extract_series(exclude=...)` 确定性剔除面板标签 / 轴标题 / 图例文字。

### 13.1 换算（**全链路最容易静默错位的一步**）

```
像素矩形 = (pt − rect_pt) × dpi/72，再按 EXCLUDE_PAD_PX(2) 外扩
```

`text_box_to_px` **单独成函数并单独测**：少减一次 `rect_pt` 偏移、或把 `dpi/72` 写成 `72/dpi`，掩码就会糊到图的另一处——**而提取结果照常产出、不会报错**。

外扩 2 px 是因为文字 bbox 紧贴字形，抗锯齿光晕会溢出 1–2 px；不外扩会让掩码边缘留下一条"文字色"的细线，在 scatter 路径下可能被当成标记点。

### 13.2 必须知道 PNG 的 dpi（`resolve_dpi`）

换算需要 dpi。两个来源，按可靠性排序：

1. **溯源 sidecar**（`from-pdf` 在 PNG 旁写的同名 `.json`）——权威值；**但只在它的 `rect_pt` 与调用方给的 `--rect` 一致时才采信**（`tol_pt = 0.5`）。不一致说明用户拿的是**另一张图**的 PNG，此时任何换算都是错的 → 拒绝采信、改用反推并告警。
2. 由 `image_width_px / rect 宽 × 72` **反推**。PNG 是 `clip=` 局部渲染，宽度严格等于 `rect 宽 × dpi/72`，反推是精确的。

两条都不成立 → 返回 `DEFAULT_DPI` **并附告警**，由调用方转达给用户，而不是静默用一个可能错的 dpi 去糊掩码。

### 13.3 掩码在连通域**之前**生效

`extract_series(exclude=...)` 在 `color_mask` 生成之后、连通域分析之前把排除区置背景（`apply_exclude_mask`），越界矩形自动裁剪，`boxes` 为空时**原样返回同一对象**。

**这是"机制生效"而非"事后过滤"**：事后把落在排除框里的点删掉，会让一个跨越排除区的连通域被**截断成两个**、或在 `min_points` 判定前就被污染；前置置背景才是语义正确的做法。测试断言了"排除整条竖带后序列点数确实下降"。

**回归红线**：`exclude=None` / `exclude=[]` 与不传该参数**逐位一致**（序列名、类型、颜色、全部点坐标完全相同）。

### 15.1 新增开关

```bash
PY=".../python.exe"; SKILL=".../chart-digitizer"
```

## 16. 端到端示例：开放脊多面板（P3 `Fig. 2`，2026-09-17 实测）

这是本链路**目前唯一一个"图例可用 + 需逐面板手工标定"**的完整实测样本，可作为同类
（多条堆叠、共用 x 轴、仅左+下脊、y 轴为 `arb. units`）文献的操作模板。

### 16.1 图内几何（全部由矢量对象量出，非目测）

| 项 | 实测（PDF 点，y 自页顶向下） |
|----|------------------------------|
| 共用 x 轴（唯一长水平线） | `y = 340.27`，`x ∈ [69.56, 287.35]` |
| 面板左脊 | 面板 1 `x = 75.88`；面板 2、3 `x = 73.96`（**顶面板偏右 1.9 pt**） |
| 面板纵向区间 | ① `y ∈ [75.86, 155.04]` ② `[168.26, 247.39]` ③ `[260.61, 339.79]`（各高 79.18，间隔 13.2） |

### 16.2 横轴标定：由**带数字的主刻度**反推

`page.get_text("dict")` 给出 `8 / 9 / 10 / 11` 四个主刻度标签（9.49 pt，**文本层，零 OCR**）；
`get_drawings()` 给出 41 条等距短竖刻线（`y∈[339,346]`，宽 0.47 pt），间距均值 **5.3645 pt**
（= 0.1 eV 次刻度）。两者对齐后取索引 5/15/25/35 的刻线 `x0 = 96.14 / 149.81 / 203.43 / 257.11`，
四点线性回归得：

```
1 eV = 53.6530 pt        四点回归残差最大 0.019 pt（≈ 0.0004 eV）
轴左端 69.40 pt → 7.5016 eV      ← 恰为 7.5，交叉验证了标定
轴右端 287.32 pt → 11.5633 eV
```

### 16.3 三条命令（逐面板）

```bash
PY=".../python.exe"; SKILL=".../scripts"
PDF="D:/WORK/KHP_C5/respond/Communications Chemistry, 4(1), 72.pdf"
RECT="48.64,51.99,288.40,368.79"

# ① 裁图（一次即可，三个面板共用同一张裁图）
"$PY" "$SKILL/chartdigit.py" from-pdf "$PDF" --figure 2 -o P3_Fig2 --dpi 600

# ② 逐面板取数：--axes 是裁图像素矩形，横轴标定三面板相同，纵轴各面板各自给
"$PY" "$SKILL/chartdigit.py" extract P3_Fig2.png \
    --axes 226,199,1989,859 --xlim 7.6202 11.5633 --ylim 0 1 --scale-x linear --kind line \
    --exclude-from-pdf "$PDF" --page 5 --rect "$RECT" --format csv xlsx json -o panel1_TPES

"$PY" "$SKILL/chartdigit.py" extract P3_Fig2.png \
    --axes 210,969,1989,1628 --xlim 7.5844 11.5633 --ylim 0 1 --scale-x linear --kind line \
    --exclude-from-pdf "$PDF" --page 5 --rect "$RECT" --format csv xlsx json -o panel2_mz70

"$PY" "$SKILL/chartdigit.py" extract P3_Fig2.png \
    --axes 210,1739,1989,2398 --xlim 7.5844 11.5633 --ylim 0 1 --scale-x linear --kind line \
    --exclude-from-pdf "$PDF" --page 5 --rect "$RECT" --format csv xlsx json -o panel3_mz115
```

**`--xlim` 的由来**：`--axes` 的左边界像素列（面板 1 = 226，面板 2/3 = 210）按 §16.2 的
映射换算得到的 eV 值（7.6202 / 7.5844），右边界 1989 px → 11.5633 eV。
这样标定由**刻度锚定**，与"轴线的端点到底在哪"这一不确定量解耦。

### 16.4 三处必须显式给出的内容与实测结果

1. **`--kind line` 必须显式给（这是对已知缺陷 R8 的规避，不是自由选择）**。默认
   `--kind auto` 下**蓝色曲线整体丢失**（只出 2/3 条）：
   `#3f3fff` 的掩码因曲线陡且**被遮挡切成数段**，每段都成为高宽比 > 2.2 的细高连通域
   → `_infer_kind` 判为 `errorbar` → 该序列点数 < `min_points` 被丢弃。显式 `--kind line`
   后 3/3 条齐。机制与证据见 §16.6。
2. **`--ylim 0 1` 声明为"面板高度分数"**。y 轴无任何数字刻度，绝对纵坐标**不可恢复**；
   交付物必须写明这一点，不得当作物理量。
3. **逐面板给 `--axes`**，因为 `detect` 只能给出一个 `open-axes` 大框（`内容占比=0.186`），
   三个面板的纵轴范围各不相同。

实测：**3 个面板 × 3 条序列全部提取成功；三个面板的图例颜色校验均 `ok=True 3/3`**
（图例画在面板 2 内，但三种颜色在三个面板里都存在）。面板 2 的 `hits` 与 `plot_hits` 相差
166 / 184 / 204 px（色块自身），面板 1/3 因色块不在其区域内而两者相等——这正好交叉验证了
§12.3 的加固项确实只在"色块落在区域内"时起作用。

### 16.5 遮挡导致的可见区间（**必须如实交付**）

| 面板 | 序列 | 提取到的 x 区间 | 原因 |
|------|------|----------------|------|

**不得**用插值补上——那是把"未观测"伪装成"已观测"。

### 16.6 R8 的机制锁定（`test_kind_auto_steep_fragmented_curve`，S3 追加 13 项）

R8 是 S3 收尾时**独立立案**的缺陷，不是本方案的既有设计：`--kind auto` 会把
**被遮挡切成多段的陡粗曲线**判为 `errorbar`，后果有两种表型——

- **表型 A（P3 实测）**：段数 < `min_points` → 序列**整条从输出中消失**；
- **表型 B**：段数 ≥ `min_points` → 序列被保住，但**标签错、点数错**（此时"点"是各段
  质心，一个段一个点，不是曲线的真实采样点）。

**根因不是「陡」，而是「被切断」**。判据是 `tall >= max(3, 0.25 * len(props))`：
单条未打断的陡曲线只有 1 个细高分量，`1 < 3` → 仍判 `line`；一旦被切成 ≥3 段，
每段都是细高分量，`tall` 就跨过阈值。**遮挡因此是触发器，不是无关变量**——
同一份数据换个遮挡状况就会换一种表现，这正是它值得用单元测试锁定的原因。

合成夹具的确定性证据（无随机性；`tests/test_extract_units.py`）：

| 夹具 | 分量数 | aspect≥2.2 | 阈值 | `_infer_kind` | `kind=auto` | `kind=line` |
|------|-------|-----------|------|---------------|-------------|-------------|
| 未打断（对照） | 1 | 1（aspect 2.51） | 3 | `line` ✔ | 1 条，250 点 ✔ | 1 条，250 点 ✔ |
| 4 段（表型 A） | 4 | 4 | 3 | `errorbar` ✘ | **0 条（丢失）** | 1 条，216 点 ✔ |
| 9 段（表型 B） | 10 | 10 | 3 | `errorbar` ✘ | 1 条，10 点（标签错） | 1 条，268 点 ✔ |

> 表中三种夹具共用同一斜率（2.5）与线宽（5），**只有「是否被切断」这一项不同**——
> 这正是"根因是切分而非斜率"的对照式证明。夹具构造与断言在
> `tests/test_extract_units.py::_frag_steep_img` / `test_kind_auto_steep_fragmented_curve`，
> 无随机数，复跑结果逐位可重复。

**未修复，只锁定**：修改 `_infer_kind` 属于改动既有判定逻辑，超出 S3 的改动权限
（SPEC 只允许追加测试与文档）。当前处置是「**文档化规避 + 单元测试锁定现有行为**」：
前者（§16.4 第 1 条、`troubleshooting.md` DP5）告诉使用者怎么绕开，后者保证该缺陷
**不会再"悄悄换一种图就消失"**。真正的修复应单独立项，且必须同时补一条线性/陡曲线的
精度回归。
