# 算法说明

本文档记录检测与提取环节的算法原理、参数依据，以及**开发过程中实测暴露的失败模式及其修正**。后一部分是维护本技能时最需要知道的内容——它们说明"为什么代码要这么写"。

---

## 1. 图像加载与前景区分

`load_image()` → `ImageData`，持有 RGB 数组、灰度图，并**自动估计背景色**（取图像四角与边缘区域的中位色）。

`foreground_mask()`：灰度低于 `dark_threshold`（默认 110）判为前景。这一路径面向**深色线条 + 浅色背景**的常见学术插图。

`grid_mask()`：亮度落在 `[140, 225]` 区间的像素判为网格线候选，用于在检测阶段抑制网格干扰。

> 局限：面向浅底深线的图。深底浅线的图需要先反相（当前版本未内置 `--invert`，如遇此类图请先手工处理或提需求）。

## 2. 轴线检测

> **前置链路**：若输入是**文献 PDF**（而不是已裁好的图片），`detect` 之前还有一段
> "PDF → 定位图 → 600 dpi 裁图（+ 图例 / 排除掩码）"的链路。它复用本章的检测思想
> （行长段搜索、多尺度搜索）但作用在 PDF 的**矢量对象**上，且**不做**面板切分——
> 开放脊面板须逐面板手工给 `--axes`。三通道定位、图注消歧、图例几何签名、颜色校验与
> 排除掩码的原理与实测依据**全部集中在 `references/pdf-legend.md`**，本节不再重复；
> 故障处置见 `troubleshooting.md` 的 `D-pdf` 节。

### 2.1 行长段搜索

`find_lines(mask, min_ratio, max_gap, orientation)` 在行（或列）方向上找连续前景段，长度 ≥ `min_ratio × 图像对应边长` 的段保留为轴线候选。

**实测失败模式**：最初实现每个方向只保留**最长**的那一段，导致多子图（caseD）完全检测不到面板——因为每个子图各自有轴框线，只留一段就把其余子图丢掉了。

**修正**：保留**所有**满足长度阈值的长段，后续再做合并与归并。这是多子图能力的前提。

### 2.2 亚像素精化

`refine_line_positions(gray, lines, orientation, span)`：对每条检出线的位置做**灰度加权质心**精化。

一条 1px 的线在抗锯齿下通常跨 2–3 个像素，取质心可把定位精度从整像素提升到亚像素。这是达成"提取精度中位数 ≈ 0.8px"的关键之一。

### 2.3 多尺度自适应搜索

`_MULTISCALE_RATIOS = (0.55, 0.42, 0.32, 0.24, 0.16)`

单子图和 2×2 子图的面板尺寸差 2 倍以上，固定阈值必然有一类失效。`detect()` 依次用上述比例搜索，取第一个能给出**几何自洽**结果（面板宽高比合理、轴线配对成功）的尺度。

比例下限 0.16 对应 2×3 布局的子图；更密集的布局需要手动 `--axes`。

### 2.4 刻度检测：自适应扫描带 + 端点补偿

刻度检测（`ticks_for_box` / `find_ticks` / `auto_tick_band`）服务于**标定审核**：它要的不是
"几个参考位置"，而是**刻度总数与间距模式**——因为"非等距"是判定"该轴不是线性刻度"的唯一几何
证据。这个用途把三个原本无害的近似放大成了缺陷：

#### 2.4.1 固定扫描带会把刻度标签算成刻度

最初用 `band=(2,12)`（轴线外侧 2..12 px 内、带内命中像素数 ≥3 即算刻度）。实测 caseA 的
轴下剖面：

```
row B+1 .. B+4 : 6 个前景像素（列 78,178,277,377,476,576）→ 刻度本体
row B+5 .. B+9 : 0                                        → 空白
row B+10 .. B+19: 13–30 个前景像素                        → 刻度数字标签
```

刻度只占 **1..4 px**，标签起于 **10 px**。`band=(2,12)` 覆盖到第 12 px，标签笔画在带内积满
≥3 行 → 被当成刻度。后果：caseA 的 x 轴被污染成 `integer-multiple`（最大/最小间隙=20），
间距规整度从 1.0 掉到 0.833。若污染方式再"不巧"一点，就会触发**错误的硬警告**。

**修正**：`auto_tick_band()` 自轴线向外逐像素推进，命中数为 0 即刻终止（撞上刻度与标签之间
的空白），命中数 ≥ 50% 跨度则判定仍在**轴线本体**上而跳过（轴线有宽度，实测对数轴 y 方向
第 1 个偏移正是轴线本身）。实测自动带：caseA x 得 `(1,4)`、caseE y 得 `(2,4)`。

#### 2.4.2 半开区间会丢掉压在轴框边界上的刻度

`find_ticks` 的 `lo`/`hi` 内部按半开区间切片，且 `lo` 先经 `int(round())`。实测 caseE 的对数
y 轴：6 个主刻度行位置是 `21, 99, 177, 255, 333, 411`，而轴框是 `top=21.5, bottom=411.389`。
`round(21.5)=22` 排除第 21 行，半开 `[.., 411)` 排除第 411 行 → **刻度数 6 变 4**。
刻度计数直接喂给间距模式判定与"每格数值"，少 2 个刻度会让两者都失真。

**修正**：新增 `pad` 参数（默认 0 保持原行为），审核路径传 `pad=1`。

#### 2.4.3 带内求和会漏掉次刻度——而次刻度才是硬判据的证据

对数轴的主刻度长约 3–4 px，**次刻度（每数量级内 2..9 位置）只有 1 px**。原先的判据是"带内
命中像素数 ≥ 3"，因此只捞得到主刻度。而整数量级主刻度恰好是**等距**的——与线性轴同形，
于是硬判据永远不成立。实测 caseE 的 y 轴因此只呈"等距 + 软提示"，而不是"非等距 + 硬警告"。

**修正**：新增 `mode="any"`（带内任一偏移命中即算），配合 `auto_tick_band` 的紧窄带宽使用。
实测效果：caseE 的 y 轴从 5 个刻度变成 **46 个**（含次刻度），间距模式由 `uniform` 转为
`nonuniform` → 硬警告成立。同一改动下 caseF 双对数两轴也转为 `nonuniform`。

#### 2.4.4 回归红线

线性轴**必须**仍判 `uniform`。实测基线（`tests/figures/` 六张图）：

| 图 | x 轴 | y 轴 |
|----|------|------|
| A 多曲线 | uniform | uniform |
| B 散点 | uniform | uniform |
| C 误差棒 | uniform | uniform |
| E 半对数 | uniform | **nonuniform**（对数轴） |
| F 双对数 | **nonuniform** | **nonuniform** |

线性轴一旦开始出现 `nonuniform`，硬警告就会产生误报——那比漏报更糟，因为它会让人开始
不信任正确的输出。改动刻度检测后**必须**用真实图复跑这张表。

## 3. 面板切分

`find_panels(img, mask, h_lines, v_lines, min_size)`：由长线段两两配对构成矩形候选，按内部前景占比 `_content_ratio()` 过滤空面板。

### 3.1 面板排序：行容差聚类

`_ROW_TOLERANCE = 6.0`

**实测失败模式**：2×2 布局的左右两个面板，其 `top` 坐标分别是 14.4999 和 14.5001（亚像素精化的结果）。用 `(top, left)` 严格排序时，这 0.0002px 的差会把左右顺序颠倒，导致输出面板顺序错乱（左右互换）。

**修正**：`_dedupe_nested()` 先按行容差 6px 把面板**聚成行**，行内再按 left 排序，行间按行中心排序。这样亚像素抖动不再影响顺序。

## 4. 曲线/散点/误差棒分离

### 4.1 主色提取

`dominant_colors()`：颜色量化（`quant=16`）做直方图，取像素数 ≥ `min_count` 的峰，按颜色距离 `merge_dist=48` 合并邻近峰，剔除与背景接近的（距离 < 60）。

**实现细节**：量化桶内用**原始像素求均值**而非用桶中心回算，避免 16 级量化的系统性偏差。

### 4.2 图元类型判别

`_infer_kind(mask, errorbar_aspect)`：按连通域形态判别

- 连通域高宽比 > `errorbar_aspect`（默认 2.2）且点数少 → 误差棒
- 连通域呈孤立团块、无细长连接 → 散点
- 其余 → 折线

`_looks_like_text()` 剔除轴标签被误当作数据点的情形。

### 4.3 空心标记

`_components(mask, close=True)` 使用 `binary_closing` 迭代 **2** 次。

**实测失败模式**：空心圆标记（散点图常见）在中空处断裂，连通域被拆成多个弧段，导致点数翻倍（实测 groupA 检出 15 个而真值 14 个）。

**修正**：闭运算迭代 2 次把中空补上，一个标记归为一个连通域。

### 4.4 抗锯齿边缘色去重（`dedupe_series`）

**这是最容易出错的一环。**

彩色曲线在抗锯齿下会派生出多条近乎平行的高饱和色带：**原色芯 + 过渡色**。颜色聚类会把它们当作不同曲线，导致序列数翻倍（实测 caseA 检出 6 条而真值 3 条）。

判定采用**点集重合率**而非平均距离：

```
candidate 中落在已保留序列 tol_px(默认 4px) 内的点占比 ≥ min_overlap(默认 0.7) → 判为重复
```

用重合率而非平均距离的原因：派生色带常只覆盖曲线的一部分（陡峭段明显、平缓段被背景淹没），平均距离会被少数未覆盖点拉高而**漏判**。

保留顺序采用**颜色相对背景的显著性**而非点数：

**实测失败模式**：抗锯齿色是原色与背景的混合，其与背景的距离必然更小；但它在某些图上像素数**反而更多**（色带更宽）。若按点数排序，会保留被冲淡的边缘色，导致曲线范围被截断——实测 y 范围从真值 `[-1, 1]` 缩成 `[-0.885, 1.006]`。

**修正**：`rank_key` 用 `-|color - background|` 排序，保留最"纯"的颜色。未提供背景色时退回按点数排序。

> 副作用：两条真实曲线若在绝大部分区间严格重叠，会被误合并。此时用 `--no-dedupe`。

#### 4.4.1 散点光晕需按标记半径放宽容差

**实测失败模式**：折线的抗锯齿边缘**紧贴曲线芯**，点对点距离判据（`tol_px=4`）足以捕获；但**散点标记的光晕位于标记圆周上**，它到标记中心的距离约等于**标记半径**（实测约 5–6px），超出容差，于是漏判。表现为散点图多出一条浅色"伪折线"——实测蓝色散点（14 点）额外派生出一条 28 点的浅蓝序列。

这一缺陷在早期未被发现，因为验证脚本对散点用例**显式传入了颜色**，绕过了自动颜色聚类路径。

**修正**：`_halo_tolerance()` 按连通域面积反推标记半径（`r = sqrt(area_median/π)`）并叠加到基础容差：

```
有效容差 = tol_px + max(候选半径, 已保留半径)
```

非散点序列或缺少面积元数据时退回 `tol_px`。

**验证**：`tests/verify_accuracy.py` 新增 `E/auto-color` 模式，对每个用例跑一遍**不指定颜色**的完整自动路径，并以「检出序列数 vs 真值序列数」为主判据。

#### 4.4.2 背景剔除阈值必须与匹配容差一致

**实测失败模式**：`dominant_colors` 原先用**硬编码 60** 剔除与背景接近的候选色，而 `color_mask` 的默认匹配容差是 **64**。这 4 个单位的窗口造成一个致命后果：

- 候选色 `(214,236,214)`（曲线抗锯齿产生的浅绿）与白背景的距离是 **61.0**，刚好越过剔除阈值 60，得以进入候选项；
- 随后以 `tol=64` 生成掩码时，该颜色**把整个浅色背景判为前景**——实测掩码像素数 72434，而提取区域总共只有 73455 像素；
- 输出一条覆盖全图的伪序列（表现为某个面板"检出 2 条"而真值只有 1 条）。

**修正**：`dominant_colors` 新增 `bg_margin` 参数，`extract_series` 显式传入 `bg_margin=tol`，使剔除阈值与匹配容差**恒等**。原理：若某候选色在给定容差下会匹配到背景，它就不可能是可用的曲线色。

**一般教训**：两个本应相等的阈值分散在两处硬编码，是典型的"延迟爆炸"缺陷。凡存在此类配对关系，必须由调用方显式传递、不得各自设默认值。

#### 4.4.3 抗锯齿色必须在生成掩码之前剔除

**实测失败模式**：浅色抗锯齿候选色进入 `color_mask(tol=64)` 后，会把图中**其它浅色元素**一并匹配进来——最典型的是浅灰网格线。实测某半对数图：

```
候选色 (244,200,200) 的掩码 = 4246 像素
其中 4 条水平网格线各占 495 像素（提取区域宽 500）
```

掩码已被网格线**主导**（4246 中约 1980 来自网格线），于是 `_column_trace` 提取出的"曲线"
其实是网格线，与真实曲线完全不重合，`dedupe_series` 的重合率判据因此失效、无法补救
（实测该"序列"到纯色芯的最近距离中位数 90.9px，<4px 占比仅 10%）。

**关键洞察**：抗锯齿像素是"纯色芯与背景的线性混合"，因此在 RGB 空间中**严格位于二者连线上**。
验证（红曲线、白背景）：

| 颜色 | 是否在 CORE→WHITE 连线上 |
|------|------------------------|
| 纯色芯 (217,55,56) | 线段端点 |
| 光晕 (244,200,200) | ✅ t≈0.71，垂距≈1.9 |
| 网格灰 (228,228,228) | ❌ 代入 t≈0.29 时 G 通道偏差 115 |

**修正**：`drop_antialias_colors()` 用「投影参数 t ∈ (0.06, 0.94)」+「到线段垂距 ≤ 14」判定混合色，
在 `extract_series` 中**于生成掩码之前**调用（仅自动颜色路径；用户显式 `--colors` 时不干预）。
按「与背景的显著度」降序遍历，保证纯色芯先入列，与候选色自身的像素计数无关。

**这个缺陷是间歇性的**——判据是「光晕色到网格灰的距离 < tol=64」：

| 图几何 | 光晕色 | 到网格灰 (231,231,231) | 是否触发 |
|--------|--------|----------------------|---------|
| `subplots_adjust` | (244,200,200) | 52.9 | 触发 |
| `tight_layout` | (241,184,184) | 67.2 | 不触发 |

即"换个图就不覆盖了"。因此该修复的回归防线是**确定性单元测试**
（`tests/test_extract_units.py::test_drop_antialias`），而不是依赖光栅化偶然性的图形测试。
这是本项目的一般教训：**机制类缺陷用单元测试锁定，集成测试只作补充**。

## 5. 标定

`Calibration` 实现 4 锚点仿射变换（支持倾斜轴）。

`from_box(left, top, right, bottom, x_min, x_max, y_min, y_max)` — 轴对齐矩形
`from_axes_pair(...)` — 直接给两个锚点，支持倾斜
`verify()` — 往返自校验：把 4 个锚点像素 → 数据 → 像素，报最大偏差
`skew_degrees` — 轴线偏离正交的角度

**实测失败模式**：`skew_degrees` 最初用 `theta % 180` 判断偏差，对完全轴对齐的情形返回 180°（假阳性，看起来像严重倾斜）。

**修正**：改为 `abs((abs(theta) % 180.0) - 90.0)`，轴对齐时正确返回 0°。

对数轴：`_scale/_unscale` 处理，`--log-x/--log-y` 开启；范围按**真值**给（不是指数）。

### 5.1 对数轴的插值形式（实测确认）

对数轴用**几何插值**而非线性插值：

```
u ∈ [0,1] 为归一化位置
线性： value = vmin + u · (vmax − vmin)
对数： value = vmin · (vmax / vmin)^u
```

实测对照（x 范围 1..1000，几何中点 u=0.5）：

| 尺度 | 中点值 | 与对数值之比 |
|------|--------|------------|
| 对数（正确） | 31.62 | — |
| 线性（误用） | 500.5 | 15.8 倍 |

往返校验：对数标定的 `to_data → to_pixel` 往返误差 < 1e-9 px（实测），`verify()` 报告 0。
锚点数值非正时 `_unscale` 抛 `ValueError` 而非静默出错——这是刻意的，静默的对数运算会产生 NaN 或复数。

### 5.2 对数轴的精度必须用「等效像素」度量

**这是本技能最容易被误判的一处。**

线性轴上 1px 误差对应固定的**绝对**误差，相对误差随数据接近 0 而发散。
对数轴上 1px 误差对应固定的**相对**误差：

```
每像素数量级 = log10(ymax/ymin) / 轴高像素
1px 的相对误差 = 10^(每像素数量级) − 1
```

| 轴跨数量级 | 轴高 | 1px 的相对误差 |
|-----------|------|--------------|
| 5 | 390px | 3.00% |
| 3 | 390px | 1.79% |
| 1 | 390px | 0.59% |

因此：**「相对误差 3%」在跨 5 个数量级的图上恰好等于 1 像素，完全正常。**
早期版本的验证脚本拿「相对误差 < 1%」做判据，得出"未达标"的错误结论——**判据本身错了**。

可比量度：**等效像素 = decade 误差 ÷ 每像素数量级**，与线性轴的 0.8px 直接可比。

实测（`tests/verify_log_axes.py`）：

| 用例 | 口径 | 等效像素 |
|------|------|---------|
| 半对数 | auto-box | 0.319px |
| 半对数 | truth-box | 0.806px |
| 双对数 | auto-box | 0.613px |
| 双对数 | truth-box | 0.858px |
| 半对数 | **误用线性尺度** | **177.9px** |
| 双对数 | **误用线性尺度** | **45.0px** |

验证脚本同时断言"误用线性尺度必须产生数量级偏差"，否则说明 `--log-x/--log-y` 是空操作
（只测正确路径无法排除开关未接线）。

### 5.3 标定审核：把「尺度」从声明变成可核对的数字

`audit.py` 的存在理由：标定的两个要素里，**范围**由外部给定（有据可查），**尺度类型**却有个
默认值 `linear`。默认值意味着"用户可能根本没想过这件事"，而漏加 `--log-y` 的后果是数值差
3–5 个数量级、输出外观完全正常。所以必须让"尺度是否核对过"成为**可追溯的事实**。

三件事：

**（一）来源标注。** 每轴记录 `source ∈ {用户指定, 默认}`。`--log-x/--log-y` 与
`--scale-x/--scale-y` 都算显式声明；两者同时给且冲突**直接报错**，不静默取其一
（静默取一是本类工具最容易犯的错）。

**（二）几何交叉校验（单向可靠）。** 把相邻刻度间隙除以最小间隙：结果近似整数 → 等距或
"等距但漏检若干刻度"；明显非整数 → **非等距**。线性轴的刻度不可能非等距，故这是一条可靠的
单向推断。反向不成立，这是数学事实：仅含整数量级主刻度的对数轴与线性轴几何同形。实现据此
分档：

| 间距模式 | 声明尺度 | 输出 |
|---------|---------|------|
| 非等距 | linear | **硬警告** + 指向 `--log-{axis}` |
| 非等距 | log | 无警告（自洽） |
| 等距 | log | 软提示：几何无法区分，请目视确认 |
| 等距/整数倍 | linear | 无警告 |
| < 3 个刻度 | 任意 | 明说"无法交叉校验"，不假装通过 |

阈值 `_INT_MULT_TOL = 0.20`：整数倍的相对偏差超过 20% 即判非等距。实测对数轴的该偏差达
0.33–0.5，线性轴仅 0.01–0.02，两者相差一个数量级以上，阈值不敏感。

**（三）逐刻度绝对值换算——最关键的一步。** 把每个检出刻度按**当前声明的尺度**换算成数据值：

```
u = (p_tick - p_vmin) / (p_vmax - p_vmin)
linear: v = vmin + u·(vmax - vmin)
log   : v = vmin · (vmax/vmin)^u          # 与 §5.1 同一插值形式
```

像素坐标取**锚点自身**的位置（x 轴取 `.px`，y 轴取 `.py`），因此倾斜轴同样成立。
> 踩过的坑：`Calibration.from_box` 构造的两个 y 锚点**共用同一个 `px`**（都在轴框左边）。
> 若 y 轴也取 `.px`，两个锚点零跨度 → 静默算不出任何刻度值。已在 `build_audit` 中显式写死，
> 并在 `tests/test_audit_units.py` 中双向锁定（既断言"陷阱存在"，也断言"取 py 能算出值"）。

**为什么列全部刻度而不是只给首末**：首末刻度常恰好压在轴框角上，与声明的范围端点必然相等
——循环论证，零信息量。真正暴露错误的是中间刻度（半对数图误判为线性时，中间刻度会算成
200/400/601/801，而图上印的是 0.1/1/10/100）。

**（四）非等距时抑制"每格"。** `step_units` / `step_decades` 取相邻刻度差的中位数，仅在间距
等距或成整数倍时展示。非等距时 46 个长短刻度取中位数会得到一个毫无意义的数字，展示它反而
误导。

**（五）确认留痕。** `--confirm-scale` 把 `reviewed_by_human` 与时间戳写入全部交付物；
**签字不消除警告**——人签字负责，机器不改口。`--strict-scale` 在此之上加硬闸门：有警告且无人
签字则退出码 4 且不写任何产物（避免"看起来能用"的半成品流入下游）。

**（六）已知限制（有意为之）。** ① 间距成 1:2 等整数倍时**不报警**——"漏检刻度"与"本来就是
这个步长"在几何上无法区分，报出来只会是误报；② 不做刻度标签 OCR，数值范围永远由外部提供；
③ 曲线贴轴处可能被计为一个刻度而导致误报，此时硬警告措辞是"请确认"且可 `--confirm-scale`
越过（见 `troubleshooting.md` AU6）。

## 6. 精度实测

测试集：6 类图（多曲线 / 散点 / 误差棒 / 2×2 子图 / 半对数 / 双对数），每类有 ground truth。

三种口径分别验证：

- `truth-box` —— 用真值轴框，隔离评估**提取算法**本身
- `auto-box` —— 用自动检测轴框，评估**检测+提取**端到端累积误差
- `auto-color` —— **不指定颜色**走完整自动路径，评估颜色聚类与去重

**线性轴**（单位：像素）

| 图类型 | 自动检测数据区 RMSE | 最大偏差 |
|--------|-------------------|---------|
| 多曲线 | 0.21 – 0.67 | 0.62 – 3.81 |
| 散点 | 0.44 – 1.09 | 0.80 – 1.73 |
| 误差棒 | 0.77（中心） | 1.01 |
| 2×2 子图 | 0.23 – 1.00 | 0.59 – 3.58 |

**对数轴**（单位：等效像素，定义见 §5.2）

| 图类型 | auto-box | truth-box |
|--------|----------|-----------|
| 半对数 | 0.319 | 0.806 |
| 双对数 | 0.613 | 0.858 |

三种口径的数值**逐条一致**（auto-color 与 auto-box 结果相同），说明自动颜色聚类不再引入额外误差。
对数轴的等效像素与线性轴同量级，说明对数分支实现正确。

中位数约 **0.8px**。最大偏差出现在曲线**陡峭段**（单位 x 跨度内 y 变化大，1px 的横向误差放大成很大的纵向误差），属该方法固有特性，非实现缺陷。

native ↔ gdw 往返一致性：最大偏差 **3.171e-05 数据单位**。

复现：`tests/run_all.py`（一键跑全部八个测试阶段：生成用例 → 提取单元测试 → 审核单元测试 →
PDF 单元测试 → API 精度 → 对数轴 → CLI 冒烟 → PDF 真实文献冒烟），明细输出至 `tests/verify_out/`。

## 7. 已知局限

1. 仅面向**浅底深线**，深底浅线需反相
2. 曲线**交叉**处会互相干扰（同色交叉尤甚），建议用 `--colors` 显式指定并分段提取
3. 高度重叠的同色多曲线可能被去重误合并 → `--no-dedupe`
4. 填充区域（area chart / 带阴影带）不支持
5. 三维图、极坐标图不支持
6. 图例若与曲线同色，可能被当作数据一并提取 → **输入是文献 PDF 时已由
   `--exclude-from-pdf` 确定性修掉**（文本层/矢量对象的 bbox 排除）；图片输入仍用
   `--region` 避开图例，或 `--exclude` 手工给排除矩形
