# Chart Digitizer — 图表数值提取

## 概述

把论文插图、实验图、屏幕截图中的曲线/散点/误差棒还原成可计算的数值表。核心设计是**双引擎**：

| 引擎 | 定位 | 适用 |
|------|------|------|
| **native**（默认） | 纯 Python（Pillow + numpy + scipy）自动分割面板 + 分离曲线 + 出数 | 批量、无人值守、任意图片格式 |
| **getdata**（复核） | 生成 GetData Graph Digitizer 原生 `.gdw` 工作区，GUI 目视核对后回读 | 关键数据、需要人工确认、投稿前把关 |

两引擎**共用同一套标定数学**（4 锚点仿射变换），因此 native 与 getdata 的结果可直接逐点比对。native↔gdw 往返一致性实测最大偏差 **3.2e-05 数据单位**。

native 引擎的序列分离轴是**颜色聚类**，因此有一个**硬边界**：

> **零彩色图（纯黑白线画）颜色引擎取不出来。** 四条曲线即使靠线宽 × 划线区分，
> 在 RGB 上也完全同色 ⇒ 只能得到**并集**，不是任何一条。
> 判据：`max(R,G,B) − min(R,G,B) > 25` 的像素计数为 **0**。
> 此时改走「**黑白线画引擎**」——按「笔画宽度 × 划线模式」分离，见下节。

选型前提（已与用户确认）：默认走 native 引擎，只在用户明确要求目视复核或数据关键时才引入 GetData。

---

## 何时使用

**触发场景**
- 用户给出图片路径/截图，要求提取其中的曲线或数据点数值
- 需要把已有文献图表转成可比对的数值（复现、meta 分析、对照实验曲线）
- 需要提取误差棒上下界
- 多子图面板（a/b/c/d）需要分别出数
- 用户提到 GetData / 读图 / 数字化 / digitize
- **用户给出的是文献 PDF，并指明"读 Figure N" / "读某张图"** —— 走「文献 PDF 工作流」一节

**不适用**
- 由数据画图 → 用 matplotlib / `nature-figure`
- 图表中的文字 OCR → 用 OCR 工具（本技能对 PDF **只读文本层，不做任何像素级 OCR**）
- 需要从图片中识别化学结构式 / 分子图 → 不适用

## 工作流决策树

```
用户给出图片
    │
    ├─ 先跑 detect 看结构是否可自动识别
    │      │
    │      ├─ 面板数 / 轴线数符合预期 ──→ 直接 extract（自动标定）
    │      │
    │      └─ 报告异常（panel=0、轴线斜、子图未分开）
    │             └─→ 读 references/troubleshooting.md，用 --axes 手动指定数据区
    │
    ├─ 标定值从哪来？
    │      ├─ 用户告知坐标范围 ──→ --xlim / --ylim（最优）
    │      ├─ 图上有刻度标签但用户未给 ──→ 先 --diag 出诊断图，
    │      │      把检测到的数据区和轴线位置报给用户，请其确认数值范围
    │      └─ 用户也不确定 ──→ 生成 --diag 图让用户看图报数（禁止猜）
    │
    ├─ 尺度是线性还是对数？（最易静默出错的一步）
    │      ├─ 用户已知 ──→ 对数加 --log-x/--log-y；线性显式写 --scale-x/--scale-y linear
    │      └─ 不确定 ──→ 先跑一次，看审核块的「警告」与「按当前标定换算的刻度值」，
    │             把两者交给用户对照图上刻度数字；或在图中看到间距不均匀/量级标注
    │             （×10ⁿ、10⁻²…10³）时按对数处理
    │
    ├─ 是否需要 GetData 复核？
    │      ├─ 否（默认）──→ 交付 CSV/XLSX/JSON
    │      └─ 是 ──→ 加 --gdw 生成工作区，--open 打开 GUI，人工核对后 dump 回读
    │
    └─ 验收：确认审核块报「警告: 无」或已 --confirm-scale；（--strict-scale 可用于强制）
```

## 文献 PDF 工作流

**用途**：吃文献 PDF，用户说"读 Figure 3"，输出 ①该图在 600 dpi 下的裁剪 PNG
（供查看/存档/复核）②该图的数值（复用 native 引擎）③该图的图例信息
（序列名 + 精确 RGB + 图元类型提示），用于自动命名与颜色校验。

**硬性边界**：零新增依赖（只用已装的 `pymupdf`）、**零 OCR**（图例文字只取自 PDF
**文本层**）、不改动已验证的 `calibration.py` / 颜色聚类 / `audit.py`。图定位有歧义时
**报错并列候选，绝不猜**。

### 三步走

```bash
PY="C:/Users/Administrator.DESKTOP-7RU274I/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
SKILL="C:/Users/Administrator.DESKTOP-7RU274I/.workbuddy/skills/chart-digitizer/scripts"
PDF="D:/WORK/KHP_C5/respond/Communications Chemistry, 4(1), 72.pdf"

# ① 列出 PDF 内检出的所有图（页码 + bbox + 来源通道 + 置信度 + 图注首行）
#    无副作用：不写文件、永远退出码 0（除非 PDF 打不开）。人机消歧的主入口。
"$PY" "$SKILL/chartdigit.py" from-pdf "$PDF" --list

# ② 裁出 Figure 2（默认 600 dpi；下限 300）。stdout 会直接打印下一步该跑的 extract 命令
"$PY" "$SKILL/chartdigit.py" from-pdf "$PDF" --figure 2 -o fig2 --dpi 600

# ③ 在裁图上取数，并顺带从 PDF 文本层生成排除掩码 + 提取图例 + 按图例配色
"$PY" "$SKILL/chartdigit.py" extract fig2.png \
    --axes L,T,R,B --xlim XMIN XMAX --ylim YMIN YMAX \
    --exclude-from-pdf "$PDF" --page 5 --rect L,T,R,B \
    --format csv xlsx json -o fig2_out
```

### 四个要点

1. **`--list` 是消歧入口，`--page` / `--rect` 是兜底。** `--figure N` 遇到同编号多候选
   会**退出码 1** 并打印全部候选，提示改用 `--page N`（1 起，同 PDF 阅读器显示的页码）+
   `--rect L,T,R,B`（PDF 点坐标，取自 `--list`）。定位失败同样退出码 1，**不猜**。

2. **`--exclude-from-pdf` 走的是"坐标排除"而非"事后过滤"。** PDF 文本层给出图内所有
   文字行的 bbox（轴标题、面板标签、图例文字）与图例色块矩形，在颜色掩码生成之后、
   连通域分析**之前**置为背景。这把 troubleshooting **B6/B7** 两条长期限制从"启发式过滤"
   升级为"确定性排除"。`--page`/`--rect` 必须与该 PNG 同源（即 `from-pdf` 用的那个矩形）。

3. **图例是可选增强，失败一律静默回退。** 图例只有"全部条目关联到色块 **且** R1 颜色
   一致性校验通过"时才被采用；否则回退自动配色，并在产物里写明"图例颜色校验未通过，
   已回退自动配色"以及图例色与图内实际主色的对照。**绝不硬用未通过校验的颜色。**
   序列名始终与颜色 hex 并存（`TD 415 K #3f3fff`），使错误命名可被发现。

4. **面板拓扑可能不匹配 `find_panels`。** "三条堆叠、共用 x 轴、仅左+下开放脊"这类
   （P3 Fig. 2 实测即是）不会自动切分，`detect` 会报"轴框未闭合"并只给一个大框。
   此时**逐面板处理**：用 `--axes L,T,R,B` 分别指定每个面板的数据区像素矩形。
   各面板通常有各自的纵轴范围，须分别标定。

### 轴范围从哪来（**没有捷径**）

- **横轴**：从图内**带数字的主刻度**反推。刻度数字可由 PDF 文本层读出（零 OCR），
  刻度线的精确位置可由 `page.get_drawings()` 读出；两者对齐后按
  `1 eV = (x_11 − x_8)/3` 建立映射，回归残差可报到 0.02 pt 量级。
  **这是人工标定，不是工具的自动行为** —— 工具本身只做几何校验，绝不臆造数值。
- **纵轴标注为 `arb. units` 且无数字刻度时**：绝对纵坐标**不可恢复**。
  此时可把 `--ylim 0 1` 声明为"**面板高度分数**"，并在交付物中如实写明
  "y 为面板高度分数，0 = 面板底、1 = 面板顶，绝对纵坐标不可恢复，只能得到相对形状"。
  **不要把 arb. units 的数字当成物理量使用。**

> 原理、实测依据与全部阈值见 `references/pdf-legend.md`；故障处置见
> `references/troubleshooting.md` 的 `D-pdf` 节。

## 黑白线画工作流（零彩色图）

**什么时候用**：图里**彩色像素 = 0**，几条曲线颜色完全相同，靠**线宽**与**实线/虚线**
区分（如 IC 粗/SC 细 × LG 实线/VG 虚线）。此时颜色轴上没有任何可分信息，
`extract` 只会给出**并集**——那不是任何一条曲线。

```bash
PY="C:/Users/Administrator.DESKTOP-7RU274I/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
SKILL="C:/Users/Administrator.DESKTOP-7RU274I/.workbuddy/skills/chart-digitizer/scripts"
```

```python
import numpy as np
from PIL import Image
from chartdigit import separate_bw, stroke_dictionary, has_color

rgb = np.asarray(Image.open("figure.png").convert("RGB"))
box = (46, 14, 616, 420)               # 数据区像素矩形，与颜色引擎同语义

# ① 先量彩色像素：> 0 就交给颜色引擎，别用本引擎
print(stroke_dictionary(rgb, box))     # 线型字典：几种线宽 × 几种划线

# ② 再取数
for s in separate_bw(rgb, box):
    m = s.meta
    print(s.name, m["width_px"], m["dash"], len(s.points), "缺口", m["n_gaps"])
```

### 五个要点

1. **`width_px` 是分类型指标，不是计量级线宽。** EDT 只在像素格点取值，故 `W` 只能取
   `{2, 2.83, 3.46, 4, 4.47, 5.66, 6, …}` 等离散档，且奇数宽的栅格带有 **+1 固有偏置**。
   **可用于判定"哪条更粗"，不可当作物理线宽写入论文。**

2. **缺口不插值。** 虚线间隙、图例遮挡都只输出**实际观测到**的点，缺口记在
   `meta["segments"]` / `meta["gaps"]`。下游能分辨"测量"与"推测"。

3. **彩色图必须让位。** `separate_bw` 在彩色图上返回空表；确需强制处理用
   `allow_color=True`（逃生门，不推荐）。理由：有颜色轴时颜色才是正确的分离轴，
   两个引擎同时出结果会给出两套互相打架的答案。

4. **接续留痕看 `meta["joined_by"]`。** `trace` = 逐列连续跟踪（最可信）；
   `extrapolation` = 几何外推接续；`isolated-pair` = 弱判据（"同类只剩两条且 x 不相交"）。
   **优先复核非 `trace` 的轨道** —— 弱判据理论上可能把两条真的互不相连的同宽曲线接成一条。

5. **不可分辨的情形不要硬做。** 判据**不是**"同线宽 + 同划线"本身 —— 自审实测：两条
   同宽（2.0 pt）同划线（实线）且**两次交叉**的曲线仍被正确分为 2 条（逐点误差中位
   0.62–0.67 px）。真正不可分辨的是同宽同划线曲线**沿 x 并入同一墨团**（相贴/并行重合）：
   实测两条紧贴 3 px 横线只输出 **1 条并集**，且 meta 中**无任何标记**表明此处发生过合并。
   遇到"序列数明显少于肉眼可见曲线数"时必须转人工兜底：回到 `getdata` 引擎，用
   `build_workspace()` 预置 N 条**命名 + 高对比显示色**的**空点集**曲线，用户在 GUI 里
   按线型逐条点取（源图全黑，显示色只为区分）。**不得把并集当真值交付。**

6. **注意两类结构失真（自审实测，尚无自动警示）。** ①**浅角交叉**会让细线沿途长出一条
   几十点的碎轨道（序列数 +1），因 `dedupe_tracks` 只在同类之间比较而漏删；
   ②**线宽比低于 0.35 的两条曲线相交**时宽度类退化为 1 类，两条各裂成 2 条（序列数 2→4）。
   交付前请核对"序列数 vs 肉眼可见曲线数"，不一致即按上一条转人工。

7. **必须用「双口径」验收，只看序列数会被骗过去。** 自审二期实测：近等宽（比 ≤ 1.19）
   或多重交叉的图上，序列数**正确**、位置误差**优秀**（P95 ≤ 1.4 px），但两条序列在
   一处交叉后**整段互换身份**（身份口径 P95 达 13–64 px）：

   | 口径 | 定义 | 反映什么 |
   |------|------|---------|
   | **位置** | 点到**最近**真值曲线的距离 | 能否用于绘图/拟合 |
   | **身份** | 点到**被匹配那条**曲线的距离 | 能否按曲线分别解读 |

   **判据**：位置优秀 + 身份差 + 错配点**连成连续区间**（不是集中在交叉点附近）
   ⇒ 属**跨缺口接错对象**。处置：查 `Series.meta["identity_warning"]`
   （这类序列实测全部为 `True`）；**只做绘图/拟合可直接用**，**要按曲线分别解读
   必须人工核对或转 `getdata` 点取**；交付说明里必须写明双口径。
   完整根因与三种**已被证否**的做法见 `references/troubleshooting.md` BW13 与
   `SPEC/bw-line-separation.md` §13。

> 原理（EDT 测宽为何免疫斜率、段数密度为何是唯一可靠的划线判据）、阈值、
> 开发期修掉的 8 个缺陷与 1 个被否决的设计，见 `SPEC/bw-line-separation.md`；
> **S1 自审结论与残余缺陷清单见同文件 §11–§12**（含谷切分实测惰性、回归护栏

## 标定协议（关键环节，务必遵守）

标定的准确性直接决定输出数值的绝对正确性，**任何情况下都不允许猜测坐标范围**。

### 优先级

1. **用户明确给出范围** → 直接用 `--xlim` / `--ylim`。最可靠。
2. **图上刻度可读且用户能确认** → 先 `detect --diag`，把轴线像素位置与检出刻度报告给用户，请其确认数值范围。
3. **需要倾斜轴标定**（轴线不水平/不垂直） → 用 `--xcal` / `--ycal` 指定两个锚点：

```bash
--xcal 78,392,0  575,392,10        # 格式 PX,PY,VALUE
--ycal 78,392,-1.2  78,15,1.2
```

4. **对数轴** → 加 `--log-x` / `--log-y`，范围仍按**真值**给（不取对数）：

```bash
# 半对数（y 为对数轴，范围 1e-2 .. 1e3）
chartdigit.py extract fig.png --xlim 0 10 --ylim 0.01 1000 --log-y

# 双对数（x 1..1e3，y 1..1e5）
chartdigit.py extract fig.png --xlim 1 1000 --ylim 1 100000 --log-x --log-y
```

### 对数轴的两个要点

**① 数值必须给真值，不是指数。** `--ylim 0.01 1000` 而不是 `--ylim -2 3`。工具内部按几何插值
`vmin·(vmax/vmin)^u` 换算，与 matplotlib 的 `semilogx/semilogy/loglog` 一致。

**② 用「等效像素」而非「相对误差」判断精度。** 对数轴上 1 个像素对应**固定的相对误差**，
其大小取决于轴跨几个数量级：

| 每像素对应 | 相对误差 |
|-----------|---------|
| 1 像素 / 5 个数量级 | 3.0% |
| 1 像素 / 3 个数量级 | 2.0% |
| 1 像素 / 1 个数量级 | 0.7% |

所以「相对误差 3%」在跨 5 个数量级的图上**恰好等于 1 像素**，是正常的；不要拿它跟线性轴的
「0.8px」直接比较。可比量度是 **等效像素 = decade 误差 ÷ 每像素数量级**。

实测（自检用例）：半对数 0.319–0.806px，双对数 0.613–0.858px —— 与线性轴同量级。
反面对照：同一张图**误用线性尺度**会给出 42–178 等效像素的偏差，连数值范围都完全错
（真值 y∈[0.05, 235] 被算成 y∈[141, 874]）。

**错误标定的危险在对数图上更大**：由于是乘性偏移，用错尺度后数值会差 3–5 个数量级，
而输出外观仍然正常。**务必先确认尺度类型再提取**。

### 强制约束

- **禁止从图上文字推断数值**。本技能不做轴标签 OCR；不确定时生成诊断图让用户读。
- 报告必须给出：数据区像素矩形、四个锚点及其数值、往返误差、倾斜角。用户应能凭这些信息独立复核。
- 数据区默认内缩 2px 避开轴框线（`--inset`）。若曲线紧贴轴线被截断，调小 `--inset`。

### 置信度判读

`detect` 报告的 `结构置信度`（0–1）综合了轴线长度占比、面板几何规整度、刻度均匀性：

| 置信度 | 含义 | 建议动作 |
|--------|------|----------|
| ≥ 0.85 | 结构清晰，自动检测可靠 | 直接提取，抽检若干点 |
| 0.5 – 0.85 | 可自动检测但存在干扰（网格线、图例、标注文字） | 必须看 `--diag` 图确认，必要时手动 `--axes` |
| < 0.5 | 结构异常（斜轴、无框线、散点无连线导致轴线不可检） | 手动 `--axes` 指定数据区，或用 `--region` 直接指定提取区域 |

## 标定审核（尺度标注 + 人工确认）

标定有两个要素：**数值范围**与**尺度类型（线性/对数）**。范围必须由外部给定（工具不做
OCR），而尺度类型的默认值是 `linear`——这正是最危险的静默错误：**漏加 `--log-y` 会让全部
数值偏差 3–5 个数量级，而输出的单调性、平滑度、小数位数全都正常，肉眼看不出来**。

因此每次 `extract` 都会输出一段「标定审核」，并把它写进**全部交付物**（CSV 头 / XLSX 的
`Metadata` 表 / JSON 的 `scale_audit`），使"尺度是否核对过"成为可追溯的事实而非默认假设。

```
======================================================================
标定审核（请人工确认后使用）
======================================================================
  x 轴: 尺度=linear（默认）  范围=[0, 10]
        刻度 6 个  间距=等距  每格≈2.00772
        按当前标定换算的刻度值: 0 / 1.98842 / 3.99614 / 6.00386 / 7.99228 / 10
  y 轴: 尺度=linear（默认）  范围=[0.01, 1000]
        刻度 46 个  间距=非等距（最大/最小间隙=5.75）
        按当前标定换算的刻度值: 0.01 / 59.1354 / … / 992.288 / 1002.57
  审核状态: 未确认
  对照方法: 把上面每一个「按当前标定换算的刻度值」与图中同位置印的数字对齐；
            任一对不上即说明尺度或范围有误（先查 ×10ⁿ 量级标注与单位）。
  警告:
    - y 轴：刻度非等距（最大/最小间隙=5.75），而线性轴的刻度必等距或成整数倍。
      **该轴很可能不是线性刻度**——请确认是否漏加 `--log-y`（当前范围 [0.01, 1000]）。
    - y 轴：**尺度取自默认值（线性），您未明确声明**。…
======================================================================
```

### 三层机制

**① 标注来源。** 每轴标注尺度是「用户指定」还是「默认」。默认出现即提示"您没想过这件事"，
与"您确认过是线性"在报告里从此可区分。要显式声明线性用 `--scale-x linear` / `--scale-y linear`
（`--log-x`/`--log-y` 是其对数形式；两者同时给且冲突会直接报错，不会静默取其一）。

**② 几何交叉校验（单向可靠）。** 刻度线的**间距模式**携带尺度信息：

| 观测 | 推断 | 动作 |
|------|------|------|
| 非等距且非整数倍 + 声明线性 | **该轴几乎必然不是线性刻度** | **硬警告**，指向 `--log-y` |
| 等距 + 声明对数 | 无法区分（整数量级主刻度与线性轴几何同形） | 软提示，要求目视确认 |
| 等距/整数倍 + 声明线性 | 自洽 | 无警告 |
| 刻度 < 3 个 | 无证据 | 明确说"无法校验"，不假装通过 |

反向推断不成立是**数学事实**而非实现偷懒：仅含整数量级主刻度的对数轴，其刻度在几何上与
线性轴完全一致。工具不掩盖这一点，软提示里直说"工具无法替您排除"。

**③ 绝对值对照（最关键的一步）。** 把检出的每个刻度按**当前声明的尺度**换算成数据值并列出来。
这一步把抽象声明变成可逐格对照的数字：

| 图 | 声明 | 算出的刻度值 | 图上印的 | 结论 |
|----|------|-------------|---------|------|
| 半对数 y | `linear` ❌ | 0.01 / 200.5 / 401 / 601.5 / 802 / 1002.6 | 10⁻²…10³ | **一眼看出错误** |
| 半对数 y | `log` ✅ | 0.01 / 0.1006 / 1.0119 / 10.18 / 102.4 / 1030 | 10⁻²…10³ | 一致 |

**为什么必须列全部刻度而不是只给首末**：首末刻度常恰好压在轴框角上，与声明范围的端点必然
相等——那是循环论证，没有信息量。真正暴露错误的是**中间刻度**。

### 人工确认留痕

```bash
# 审核人核对无误后签字：把确认动作与时间戳写入全部交付物
"$PY" "$SKILL/chartdigit.py" extract fig.png --xlim 0 10 --ylim 0.01 1000 \
    --log-y --scale-x linear --confirm-scale --format csv xlsx json -o out
```

- CSV 头写 `审核状态: 已确认 2026-09-16T22:24:07+08:00`
- JSON 写 `scale_audit.reviewed_by_human = true` / `ready_for_downstream = true`
- **签字不消除警告**——人签字负责，机器不改口。警告原文一并留档。

### 自动化场景的硬闸门

```bash
--strict-scale    # 审核有警告且无人签字 → 退出码 4，且不写出任何交付物
```

供上游流水线把关。已确认（`--confirm-scale`）可越过警告——这正是"交由人工审核"的落地形式：
机器报警，人签字负责。注意 `--strict-scale` 拒绝时**不产生半成品文件**，避免"看起来能用"
的产物流到下游。

### 已知限制（有意为之，不是缺陷）

- **刻度间距成 1:2 等整数倍时不予报警**。因为"漏检了刻度"与"本来就是这个步长"在几何上
  无法区分，报出来只会制造误报。此类情形仅保留软提示。
- **不做刻度标签 OCR**。几何校验只判断"间距模式与所声明的尺度是否自洽"，不读取标签数字。
  数值范围永远由外部提供。
- 曲线恰好贴着轴线处可能被计为一个"刻度"，导致间距被判为非等距。此时硬警告的措辞是
  "请确认"，且可用 `--confirm-scale` 越过。

## 任务分类

### A. 多曲线折线图

曲线颜色差异明显时全自动。结果按颜色命名（`c1_<hex>`）。

指定颜色可提升鲁棒性：
```bash
--colors '#d62728' '#1f77b4' --names 'exp' 'calc'
```

**抗锯齿边缘色去重**默认开启：一条抗锯齿曲线会被分成"纯色芯 + 边缘过渡色"两组，去重逻辑按点集重叠率 + 背景显著度排序，保留纯色芯。若同色多曲线被误合并，用 `--no-dedupe` 关闭。

### B. 散点 / 实验数据点

`--kind auto` 会依据连通域形态自动判别。实心/空心标记均可（空心标记用形态学闭运算补洞）。被误判为文字标注的稀疏序列可用 `--min-points` 调整（默认 8）。

### C. 误差棒

误差棒本体是细长连通域（高宽比 > `--errorbar-aspect`，默认 2.2），与中心点分离。输出：

- `<name>` — 中心值
- `<name>_yerr_low` / `<name>_yerr_high` — 下/上界

### D. 多子图面板

`find_panels` 用多尺度轴线长度占比搜索（0.55 → 0.16）切分子图，按阅读顺序（行容差聚类 → 行内按 x）编号，`--panel N` 选择（1 起）。

```bash
# 2×2 子图，逐个面板提取（每个面板的坐标范围可能不同，需分别给）
chartdigit.py extract fig.png --panel 1 --xlim 0 10 --ylim -1.1 1.1
chartdigit.py extract fig.png --panel 3 --xlim 0 10 --ylim 0 3.4
```

要点：
- 多尺度搜索是 `--min-ratio` 的**默认**行为（不要手工设成固定值，否则密集布局会整个漏检）
- 每个面板独立标定，`--xlim/--ylim` 按该面板的刻度分别提供
- 面板编号可用 `detect` 查看（诊断图上也会标注）

### E. 对数坐标图（半对数 / 双对数）

加 `--log-x` / `--log-y` 切换对应轴为对数刻度，数值范围按**真值**给：

```bash
# 半对数：y 对数（1e-2..1e3），x 线性
chartdigit.py extract fig.png --xlim 0 10 --ylim 0.01 1000 --log-y

# 双对数
chartdigit.py extract fig.png --xlim 1 1000 --ylim 1 100000 --log-x --log-y
```

**必须核对报告中的 `尺度=` 一行**（如 `尺度=(linear,log)`）。漏加开关会导致数值差
3–5 个数量级，而输出外观完全正常。精度评价用「等效像素」而非「相对误差」——
详见上文"标定协议 → 对数轴的两个要点"。故障排查见 `references/troubleshooting.md` 的 B-log 节。

### F. 恒等式 / 求和规则审计（数字化的高阶用法）

图里同时画了"总计"与若干"分项"，且二者**理论上应满足某个恒等式**时，数字化不止是抄数，
而是可以**反推该图隐含的未声明项**。典型恒等式：`σ_total = Σσ_f`、分支比之和 = 1、
`I_total = I_core + I_valence`、能量守恒/归一化闭合。

**步骤**

1. 同面板所有曲线用**同一套标定**提取到公共 x 网格。技巧：只要各曲线的 y=0 都落在同一底框，
   **比值 `total/Σparts` 与 y 尺度无关**——y 量程不确定时也能算，先出比值再补绝对值。
2. 算残差 `R(x) = total(x) − Σparts(x)`，以及 `ratio(x) = total(x)/Σparts(x)`。
3. 按形态判读：
   | 形态 | 含义 |
   |---|---|
   | `ratio ≡ 1`（±1–2%） | 恒等式成立，数字化结果可作交叉校验 |
   | `ratio` 在某处孤峰、别处回到 1 | 存在**未画进分项的额外项**（常见：共振/中间态/多极项），且该项在别处衰减 |
   | `ratio` 全局偏离某一常数 | 分项口径不一致（单位、前因子、不同理论模型拼接） |
4. **归因（这一步才是价值所在）**：把残差峰的位置、宽度与该文**独立的参数表**（极点能量、寿命、
   Γ、峰宽）逐项对照。若吻合到绘图分辨率量级，即可判定该项是**外挂**的，而非从分项动力学中涌现。
5. **廉价强化判据 — 1/Γ 标度**：同族多个体系的"峰值残差 × 该峰 Γ"若近似为常数，则确认残差项
   是以洛伦兹极点形式加入的。若峰是真实动力学产物，绝不会出现这种跨体系反比关系。

**工程要点（易踩）**

- 校准先用**已知物理阈值**交叉核对（如脱附阈值应等于某分项曲线的起点）；偏差 > 0.05 eV 就重标定。
- **遮挡是最大障碍**：图例框、分子式标签、轴标题会把"取每列最上/最下像素"的算法污染成假峰。
  必须先按包围盒掩膜排除，并**输出叠加图（检出点画回原图）目视复核**——只看数值表发现不了。
- 纵向不确定度按**满量程百分比**报（本类图 ±2% 满量程）；峰顶会被原始绘图的能量采样步长压低，
  报出的峰高是**下界**。

- 改了刻度检测或审核逻辑 → 必须看 `test_audit_units.py`；修改后需用真实图复跑
  `ticks_for_box`，确认**线性轴仍判 `uniform`**（否则会开始产生硬警告误报）
- **改了 `bwline.py` → 必须看 `test_bwline_units.py`（机制）与 `verify_bw_accuracy.py`（精度）两个都要跑**。

## 验收清单

交付前逐项确认：

1. `detect --diag` 的诊断图中，检出框落在数据区上，提取点贴住曲线
2. 报告的锚点数值与图上刻度一致（**若不一致，数值全部作废**）
3. **报告的尺度与图一致**（`尺度=(linear,log)` 等）—— 对数图漏加 `--log-y` 会差 3–5 个数量级
4. **审核块的「按当前标定换算的刻度值」与图中同位置印的数字逐一对得上**（这一步是最短的
   闭环检查：任一中间刻度对不上，即说明尺度或范围有误）
5. 审核块报「警告: 无」，或警告已逐条核对并加 `--confirm-scale` 留痕；未确认的产物**不得**
   直接用于下游分析或发表（自动化场景用 `--strict-scale` 强制）
6. 往返误差 ≈ 0px、倾斜角 ≈ 0°
7. 检出序列数与图上实际曲线/散点组数一致（多一条常是抗锯齿或轴框，见 `troubleshooting.md` B1）
8. 输出数据的范围与图上目视范围一致（**对数图上按量级核对**，不要只看是否单调）
9. 需要投稿把关时，加 `--gdw` 走 GetData 目视复核
10. **（文献 PDF 链路）图例颜色校验通过，或已明确回退自动配色**。走 `--exclude-from-pdf`
    时，产物里的「图例」区块必须给出三种结局之一，且都能解释：
    - **校验通过** → 序列名为「图例名 + hex」，配色取自图例（此时仍应目视核对一次配色是否正确）；
    - **未检出图例** → 正常（期刊常把颜色含义写在图注文字里而不画图例），回退自动配色；
    - **校验未通过 → 已回退自动配色** → 报告会列出图例色与图内实际主色的对照，**须人工判定**
      是"期刊对色块做了淡化/换色"还是"区域取错"。
    三种情况都**不应**让退出码非 0——图例是可选增强，失败不改链路结局。
11. **（文献 PDF 链路）轴范围的来源必须能说清**。横轴须由图上**带数字的主刻度**反推并说明
    依据；纵轴若标注为 `arb. units` 且无数字刻度，须在交付说明里写明"y 为面板高度分数，
    绝对纵坐标不可恢复"，**不得**把该数字当作物理量使用。
12. **（黑白线画链路）** 交付前确认：
    - 彩色像素数确为 0（`stroke_dictionary` 的 `color_pixels`），否则应走颜色引擎；
    - 检出轨道数 = 图上曲线数；每条轨道的 `dash` 与图例/图注所述线型一致；
    - `meta["gaps"]` 与图上可见缺口逐一对应（**缺口内不得有点**，即未插值）；
    - `meta["joined_by"]` 非 `trace` 的轨道**已人工复核过接续是否正确**；
    - `width_px` **只用于说明"哪条更粗"**，不得作为物理线宽写入下游或论文（见限制 1）。
