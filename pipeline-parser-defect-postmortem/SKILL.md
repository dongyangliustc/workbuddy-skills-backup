# 流水线解析端缺陷：发现 → 修复 → 回滚重算

适用场景：一个已上线的自动化流水线（作业状态机 + 确定性解析器 + 报告层），
在**真机产物**上暴露"抽取类"缺陷 —— 作业其实成功，但被误判失败；或数值被静默写错。

## 0. 症状分诊（第一步，别急着改正则）

**判别规则：同一批次、多个作业、同一编码、同一严重级别 → 优先怀疑执行端缺陷，而不是 N 个独立科学失败。**

证据动作：
- 随机抽 2–3 条被判失败的产物，逐个确认是否真的失败（grep 终态标记）。
- 若产物含成功标记（如 `Normal termination`）→ 执行端缺陷，停止把它当科学失败。
- 统计该编码命中的作业数；命中率 ≈ 该批次正常作业数 = 系统性缺陷。

## 1. 用真实产物定位，不要用"我以为的格式"

- 直接从真实产物里 grep 目标字段的**原始行**，不要凭记忆写正则。
- 关键：真实软件常有**多种等价打印形式**（例如 Gaussian 静态极化率同时有
  `Exact polarizability: XX XY YY XZ YZ ZZ` 六元组行与
  `Isotropic polarizability for W= 0.000000 XX.XX Bohr**3` 汇总行）。
  优先取精度高的一支，并用另一支做**交叉印证**（两者算出的值必须一致）。

## 2. 夹具政策：夹具必须是真实产物

- **合成夹具只会"验证"你写的正则**。若夹具是照自己的假设写的，测试通过没有任何信息量——
  它恰好会掩盖真机格式差异。
- 做法：夹具 = 真实产物**逐字节副本**（保留全部原始行、包含多步/多块结构）。
- 必须加**反证测试**（证伪式断言）：
  - 喂入"你以为存在但真实软件从不输出"的旧格式 → 必须返回 `None`（宁可报缺失也不接受不存在的格式）。
  - 多值块字段：断言"取到末块值 **且不等于**首块值"。
- 若日志是多步（如 Link1 `Opt`|`Freq` 两段），`Normal termination` 会出现**多次**——断言次数本身要写对，
  否则你会为了迁就夹具去"修正"本来正确的行为。

## 2.1 修复后必须证明新测试「非空」（变异测试）

**"加了回归测试" ≠ "回归测试能捕获该缺陷"。** 永远通过的空测试会假装保护你。
判定手段只有一个：**把缺陷注回源码里，看测试是否变红**（mutation testing）。

步骤：
1. 备份原文件字节；逐条列出 `(变异描述, 旧片段, 新片段, 必须失败的测试名)`；
2. 对每个变异：写入变异源码 → **子进程**跑测试模块 → 断言预期测试全部失败；
3. `finally` 还原，并用 **sha256 校验字节级复原**（不一致必须报错退出，不能静默）。

**陷阱一：进程内 monkeypatch 会给出假阴性。** 测试模块用
`from X import f` 绑定了名字，于是 `patch(X.f)` 改不到测试自己那份引用，
直调 `f` 的用例**照样通过** → 你会误判"测试没捕获缺陷"。
凡是要证明"测试能否捕获"，**必须变异源码文件并开子进程重跑**；进程内 patch 只适合验证调用链内部的副作用。

**陷阱二：字节码缓存会掩盖变异。** 变异前后的文件若尺寸/时间戳不足以使 `.pyc` 失效，
可能跑到旧字节码。每次变异前清掉 `__pycache__`，并设 `PYTHONDONTWRITEBYTECODE=1`。

**陷阱三：测试夹具里的键名要与真实数据一致。** 例：Crossref JSON 的键是 `published-online`
（连字符），写成下划线后 `item(**{...})` 静默多出一个无效键，解析器回退到 `issued`，
断言随之失败——**这是夹具错误，不是代码缺陷**。收到红测试时先分清"代码错"还是"夹具错"。

## 3. 多值块的取值口径必须显式统一

同一字段在不同位置会重复出现（每优化一步打印一次）。**必须显式声明取首/取末，并全字段统一。**

- 常见正确口径：SCF 能量、基函数数、偶极、极化率 → 全部取**最后一次**（对应最终几何）。
- 历史教训：一个模块里 SCF 与 NBSuse 注释写了"取最后一次"，偶极却用了 `.search()` 取首块 →
  静默写入**优化中途**几何的值。**不产生假阳性，因此比误判更隐蔽。**

## 3.1 量化修复影响：同记录集单变量 A/B

**上游数据源会漂移**（重跑一次 API，返回的记录集就变了），所以"修复前那批 vs 修复后这批"的
对比**不是对照实验**，无法归因。做法：

1. 先跑一次**修复后**的抓取，落盘为新 harvest（**不要覆盖**本周已发布的审计 harvest，那是审计证据）；
2. 复制该 harvest，把**唯一被测字段**改回旧值（如 `published = None`），其余字节不动；
3. 用同一评分/解析函数跑两遍，比较**同一批记录**的分数差 → 差值只能归因于该字段；
4. 再用 spec 认可的工具（如 `calibrate_discovery.py`）复算一次，作为可引用的独立口径。

**陷阱：delta 小于配置的奖励值 ≠ 有 bug。** 评分器普遍有 `max(0, total)` 地板：
原始总分为负的记录被截断到 0，加 2 分奖励只抬升 1 分甚至 0 分。
判定方法：另算一份**未截断**总分，若"所有 delta < 奖励值 的记录，其未截断旧总分均 ≤ 0"，
则全部由地板解释。**先算未截断值再下结论。**

## 4. 回滚通道设计（最难的一步）

终态化状态机（如 `FLAGGED` 被定义为终态，达门判据依赖它）会与"修 bug 后重算"冲突。
两种错误做法：

- ❌ 放宽通用跃迁表（把 `FLAGGED → RETRIEVED` 加进 `ALLOWED_TRANSITIONS`）→ 破坏"终态"语义，
  达门/汇总判断会失效。**不要动通用跃迁表。**
- ❌ 手工改状态文件 → 无留痕、不可复现、下次不知道谁改的。

✅ 正确做法：**受控窄通道**，独立于通用跃迁表，且必须满足：

1. 必填 `defect_ref`（缺陷编号）+ 非空 `reason`，缺任一即抛错；
2. **编码白名单**——只允许"纯抽取类"编码（缺失/不自洽/计数错）；
3. **科学失败黑名单**——错误终止、虚频、非稳态点等一律拒绝。**加第二道保险**：
   重算前读产物，含 `Error termination` 或缺少成功标记 → 直接跳过。两道都要，防止白名单被误用；
4. 非终态作业（如"已解析、等待补救"）**只结案假阳性、不改状态**，否则会吞掉真实异常；
5. **台账只加不删**：原条目保留，只补 `resolved_by = "DEFECT:<ref>"`；
6. 事件日志留痕 + 作业内追加 `reopen_history`。

CLI 形态：`--reopen-code <编码> --defect <编号> --reason <说明>`。

## 5. 证据持久化（否则报告里的路径会失效）

- 失败作业的产物必须**主动留档**：异常台账通常记的是**远端/临时路径**，而远端目录随时会被清理。
  检索循环原本只回收"成功"作业 → 失败作业的证据会永远丢失。
- 给异常条目补一个 **`local_evidence`** 字段（只加字段，不改旧值），报告渲染时优先显示本地持久副本。
- 报告层取值要**跟随 `result_source`**：补救成功时父作业的 `parsed` 仍停在触发补救那一步，
  直接读父作业会漏字段或用旧值。统一走 `adopted_job()/adopted_parsed()` 间接层。

## 5.1 「只读 / dry-run」开关必须早于任何写

**典型缺陷形态**：写分支（尤其是"什么也没发现"的早退分支）**排在** `if dry_run:` 之前，
于是"dry-run 恰好没找到东西"时反而写盘 —— 无写入承诺被静默违反。

- 实例：`if not added:` 分支无条件写 discovery log + 更新 seen-list，而它位于 dry-run 检查**之前**。
  后果：一次探查性 dry-run 用「111 重复 / 165 剔除」覆盖了真实运行的「123 重复 / 277 剔除」，
  **抹掉审计痕迹**（而且不会报错，只在 `git status` 里显出被改的文件）。
- 规范：`dry_run` 判定放在**函数内第一个可能写盘的位置之前**；早退分支不得先写后判。
- 测试：断言"**零文件生成**"（日志目录不存在、状态文件不存在、registry 字节不变），
  并配一个"非 dry-run 仍然写"的对照用例——否则测试可能因夹具路径不对而假绿。
- 排查手法：跑完只读命令后立刻 `git status --porcelain`，**看有没有你预期外的 M**。
  这是发现"偷偷写盘"最快的信号，应在每次只读操作后习惯性执行。

### 审计日志被误写后的恢复

优先找**幂等重放**路径：本例重跑原 ingest 命令即恢复（零新增路径只写日志/seen，不碰 registry，
输入未变则输出确定）。判据：① 恢复后 registry 的 sha256 未变；② 下游产物（周报）重生成**字节一致**。
两者同时成立才能宣称"恢复忠实"。

## 6. 收尾清单

- [ ] 全量测试通过（含新增的反证测试）。
- [ ] **新增测试已通过变异测试证明非空**（注回缺陷 → 测试变红 → 源码 sha256 复原）。
- [ ] **dry-run/只读开关已确认早于所有写**；跑完只读命令后 `git status --porcelain` 无预期外改动。
- [ ] 修复影响用**同记录集单变量 A/B** 量化过，未截断总分已核对（排除地板效应误判）。
- [ ] 用修好的代码**在真实产物上重算**，逐条确认违规数为 0。
- [ ] 台账未结案数下降；剩余未结案必须每一条都是**真实**现象。
- [ ] 报告/汇总里的陈旧数值已更正（并在修订说明里写清"据 X 缺陷更正"）。
- [ ] 快照留档（重算前后各一份）。
- [ ] 把该缺陷写进当日日志 + 长期笔记的"必须遵守的执行端事实"。

## 反模式速查

| 反模式 | 后果 |
|---|---|
| 先改正则再找真实格式 | 反复试错，可能"修"成另一个错格式 |
| 合成夹具 + 正向断言 | 缺陷被测试"认证"，一路活到真机 |
| 只加回归测试、不验证它会变红 | 空测试假装保护你，缺陷可复发 |
| 用进程内 patch 验证"测试能否捕获" | `from X import f` 绑定使 patch 打空 → 假阴性 |
| 用"修复前的批次 vs 修复后的批次"对比 | 上游数据漂移，差值无法归因 |
| delta < 配置奖励值就判定有 bug | 忽略 `max(0, total)` 地板，误修正常逻辑 |
| dry-run 检查排在写分支之后 | "无写入"承诺被静默违反，审计日志被覆盖 |
| 只读命令跑完不看 `git status` | 偷偷写盘不报错，痕迹丢失无从察觉 |
| 宣称"日志已恢复"却不验下游产物 | 掩盖恢复不忠实（应比对重生成产物字节） |
| 逐条手改状态文件 | 无留痕、不可复现 |
| 放宽通用跃迁表 | 破坏终态语义与达门判据 |
| 只加白名单不读产物 | 误用通道会把真·科学失败洗白 |
| 只回收成功作业 | 失败证据丢失，"为何失败"不可回溯 |
