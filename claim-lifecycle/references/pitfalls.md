# 工程经验与踩坑记录（Pitfalls）

沉淀自 2026-08-26 球面波知识库试点（2066 chunks、14 条主张、门控验证），对任何"自产知识同流"场景通用。

## 1. 自锚定失真（最易踩）
**现象**：capture_claims 首次运行，所有主张都命中自身 own-note chunk（字面命中 score 128–146 最高），全部被自证。
**根因**：检索锚定时没有排除"主张所属来源自身的 chunk + ideation provenance"。
**修复（硬规则）**：
- 锚定证据**必须排除 `ideation` provenance 的 chunk**（自产不能当自己证据）；
- 必须排除主张自身来源文档（`source_id` 匹配）；
- 判定层级用来区分 T0/T0* 与 T1，而不是"命中即支持"。

## 2. 机器只锚定、绝不升级
- 自动锚定只能给 `consistent`（有非自产弱锚）或 `unverified`（无锚）。
- `literature_supported` 只在该 chunk 字面命中且 score ≥ 100（T0/T0* 来源）时由机器**建议**。
- 任何人工升级必须在周报复核门槛人工裁决——机器升级 = 自证污染。

## 3. 弱锚点漂移风险
score 1–30 的弱命中与主张语义未必一致。`consistent` 不等于正确，只是"有线索"。靠周报逐条人工复核兜底。

## 4. 门控位置：检索层，不是入库层
- 入库不设限（所有知识都进同一条管道，保证全量召回能力）；
- 出库严把关（注入/交付时按 `min_epistemic_status` 过滤）。
- 若在入库层就拦掉自产知识，"同流"名存实亡，检索死角扩大。

## 5. 双轴绝不合并
"谁说" 与 "验证过没有" 是两个正交维度。合并成一个标签（如"低可信自产"）会丢失：T0 文献里未达 `rank≥2` 的断言、T2 自产里已 benchmark 验证的结论。

## 6. 状态机粒度
`confidence/review_status` 若只到"文献条目级"无法管理自产知识真伪——必须下沉到**主张级**，chunk 通过继承规则（fail-closed）兜底。

## 7. 拉动节点
- MCP connector / 检索服务改动后需重启才生效（新工具、新参数不会即时出现在运行中会话）。
- 索引重建后要重新核对 chunk 分布（source_type 默认标签与预期是否一致）。

## 8. 测试维护
- 工具集断言会随新工具过期（如 server 工具从 3 个增到 7 个），版本升级时同步更新测试。
- 跨平台路径断言用 `is_absolute()` + 规范化后缀匹配，勿直接比较 resolved 绝对路径（Windows 盘符语义）。
