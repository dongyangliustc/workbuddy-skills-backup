# 优化收益核算审计

## 何时使用

- 要为一个新的计算加速方案（粗网格 + 插值、降采样、批处理、近似求值器）给出加速比
- 已有加速比估计需要复核（尤其"名义 N 倍"类）
- 实测加速比**远低于**名义倍数，需要定位差异来源
- 实现"开关式"优化，需要验证开关确实生效

## 三条硬规则

### 规则 1 — 代价随位置分布必须先实测，不可假设恒定

**反例（真实案例）**：假设"交换势 V_x 单点代价恒定"，按
`点数 × 恒定 ms/pt` 外推到网格规模 → 得到 217 h。
**实测**：单点代价在 r = 0.02 … 12 a₀ 恒为 ~104 ms（散布仅 3.5%），
**与位置完全无关**；代价 ∝ `基函数对数 × 角向点数`。

**做法**：在 5–10 个代表性位置上计时，报告**均值和散布**。
若散布 < 20% → 代价在位置上平坦；否则必须分段建模。

```python
for probe in representative_points:      # 覆盖内层/中层/外层
    t0 = time.time()
    for _ in range(3): f(probe)
    print(f"{probe}  {(time.time()-t0)/3*1000:.2f} ms")
# 关键：报告 std/mean。>20% 说明不能当常数处理
```

### 规则 2 — 找出"免费区"，它决定收益上限

早退守卫（密度屏、`|x| < eps` 检查、对称性剪枝）会把大量工作点
变成近乎零成本。

**真实案例**：ρ 屏阈值 1e-10 使生产网格 6000 点中
**4738 点（79%）免费**（1.98 ms vs 88 ms，**44×**），
只有 **1262 点（21%）**付全价。

**推论（最易错的一点）**：优化方案的收益**只作用于昂贵区**。
若优化后的采样点仍**全部落在昂贵区**，则加速比是

    S = k / (frac·k + 1 − frac)        frac = 昂贵区占比

而非名义 k。k → ∞ 时 **S → 1/frac**（此例 4.76×）。

**若优化把采样点数从 n_src 降到 n_src/k**（源点止于截断点），
则当 `k > 1/frac` 时 **S = k**（线性饱和），
当 `k < 1/frac` 时被上式压制。

> **务必先数清"昂贵区有多少点"，再谈加速比。**
> 直接测量：对生产网格逐点判定是否触发早退：
> ```python
> alive = np.array([survives_early_exit(x) for x in grid])
> frac = alive.mean()
> print(f"expensive {alive.sum()}/{len(grid)} = {frac:.1%}")
> ```

### 规则 3 — 断言受控路径非平凡执行（防空测试）

**真实案例**：在 H₂ 上跑 L3 优化 gate，得到 `Δσ = 0.000e+00`、
加速比 `1.02×` —— 表面"完美通过"，实为**空测试**：
H₂ 阳离子 `n_active = 1`，自相互作用防护把 V_x 整体置零，
优化**无从作用**。

**通用判据**："零差异"既可能是"实现正确"，也可能是"根本没跑"。
**同一份输出无法区分二者。**

**做法**：gate 开头显式断言受控对象非平凡：

```python
if n_active <= 1:
    print("VACUOUS TEST ABORT: optimized path has nothing to act on")
    raise SystemExit(2)          # 拒绝把 Δ=0 当作证据

# 或直接断言中间量非零
mid = compute_intermediate()
assert np.abs(mid).max() > 0, "controlled path produced nothing"
```

**另一形式**：直接测"开关开/关的中间结果差异"
（本例：`max|V00(k=5) − V00(k=1)| = 4.58e-02 ≠ 0` → 确实生效）。

### 规则 4 — 计价模型必须先与「冻结锚」对账，再据此下结论

任何"点数 × 单位成本"的分解式估算都会继承单位成本的误差。**先让模型复算一个
已冻结的实测总量**（基线锚），偏差不达标就**不许使用**该模型产出的任何倍数。

```python
t_ref = cost_from_counts(ref_alive * N_ang, ref_dead * N_ang)
rel = abs(t_ref - T_ANCHOR_S) / T_ANCHOR_S
print(f"REF self-check: {t_ref:,.1f} s vs anchor {T_ANCHOR_S:,.1f} s ({rel:.5%})")
assert rel < 0.01, "cost model does not reproduce the frozen anchor"
```

**真实案例**：分解式模型复算基线得到 26,377 s，冻结锚 26,353.3 s，
**偏差 0.091%** ⇒ 之后由同一模型给出的 3.104× / 4.755× 才可信。
反例：若先前的 19.7% 归因是错的，任何基于它的门槛都会"结构性不可达"——
所以对账不仅是精度检查，也是**门槛量纲正确性**的检查。

### 规则 5 — 任何比值型判据，分母是什么必须写进代码

单元量比值（"余量"、"倍数"、"偏差"）的分母极易被写错，而且**不会报错**。

**真实案例**：一个"分辨率余量"字段把 `L_min` 除以 `h`（0.05 a₀），
而判据是 `L_min ≥ 3h`（0.15 a₀）⇒ **余量被放大 3×**（14.86 而非 1.65），
表面上"余量巨大"。更正时须在产物内留下
`_field_correction`（原值 / 更正值 / 理由 / "未改动任何实测量"声明），
并在代码里加恒等式断言：

```python
L_thresh = 3.0 * h
assert abs(L_thresh - L_C) < 1e-12, "boundary no longer equals the classification constant"
```

### 规则 6 — 用粗扫描求"极小值"会系统高估，判 PASS/FAIL 前必须去偏

若判据依赖某个量的**最小值**（特征长度、间距、裕度），而它是从**粗网格扫描**
得到的，则扫描步长会漏掉样本间的极小值 ⇒ 测得值**偏大** ⇒ 判据偏乐观。

**做法**：① 在自己的粗/细配对上先量偏差（真实案例：同一射线粗扫 0.01828
vs 细算 0.01662，**高估 10%**）；② 施加去偏因子（如 ×0.90）后再判；
③ 设**阳性对照**——拿一个上游已测过的点复算，证明本探针未漂移
（真实案例：对照点测得 0.27513 vs 上游 0.25513，偏差 7.84% ⇒ 探针可信）。

> ⚠️ 去偏方向要写清楚：高估最小值 = **低估风险**。所以去偏是**加严**判据，
> 不是放宽。

### 规则 7 — 「构成比」≠「贡献比」，且**不可跨例程外推**

在**某个例程内部**测得的分桶占比（"A 占该例程成本的 80%"）只回答
"这个例程内部谁最贵"。要得到"A 占**整个计算**的多少"，必须再乘上
**该例程占整体的份额**——而且**同一个名字可能有多个变体，构成比完全不同**。

**真实案例（2026-09，代价核算）**：终端报告写"杠杆几乎全在 Boys 求值本身
（占 J 成本 76–82%）"，据此把一个方向列为最高优先。
实测两点：

1. 那个 76–82% 是在**向量化、预算核**的变体里测的；
   **生产热路径用的是标量变体**（每次调用重建核），其中 Boys 只占 **21.1%**。
2. 标量变体里真正的大桶是"每次调用的核重建 + 收缩"（46.3%）与"递推"（32.6%）。

⇒ 该方向对整体的理想效应从"4–5×"落到 **1.26×**（实测两路互证：20.1% / 20.3%）。
**方向选错了，是作用域外推造成的，不是测量误差。**

**做法**：
- 报任何构成比**必须写明例程名与变体**（"向量化 X" vs "标量 X"）。
- 换算贡献比时**逐级相乘并逐级给出分母**：`本桶/例程 × 例程/整体`。
- 同族例程的构成比**不可互相借用**；两变体若分桶差异大，须各测一次。

```python
# 贡献比 = 构成比 x 例程份额，两级都要有实测分母
f_bucket_of_routine = bucket_t / routine_t          # 例程内构成比
f_routine_of_total  = routine_t / total_t           # 例程占整体
print(f"contribution = {f_bucket_of_routine*f_routine_of_total:.2%}"
      f"  (routine share {f_routine_of_total:.2%})")
```

### 规则 8 — 单层挂钩给出的占比**只对该层成立**：被测函数内部的同类调用会漏掉

给某个函数挂计时挂钩，统计它占整体的比例——这是最常用的占比测法。
但它只覆盖**该层**的调用。若**被它调用的函数内部还会再发同类调用**，
占比会被系统性低估。

**真实案例（紧接规则 7）**：挂钩外层批量 J（每角向节点一次）得到
"J 占构建 **2.90%**"；而交换求值器内部**每个场点再发一次标量 J**，
J 的真实份额是 **~99%**。**低估 34 倍**，且表面完全自洽
（调用数、单次耗时都合理），只有把内层也挂上才发现。

**做法（挂钩前必做）**：
1. 对被测函数做**调用图穷举**：`grep` 它调用的每个名字，
   找出**同语义不同实现**的变体（如 `X_on_points` vs `X_at_point`）。
2. 挂钩数 = 该语义在**所有层**的出现数；逐层分别报占比，别合并成一个数。
3. **阳性对照**：断言每层挂钩的调用数 > 0（任一层恒 0 = 漏挂）。
4. 用**两路独立口径互证**总量（例：分桶占比 × 总量 ｜ 调用数 × 单次实测成本），
   两路不一致即为漏层信号。

```python
assert outer.calls > 0 and inner.calls > 0, "a hook never fired -> missing layer"
# 两路互证
route_a = inner.t + outer.t                     # 分桶加总
route_b = n_active_evals * t_inner_per_eval     # 计数 x 单次成本
assert abs(route_a - route_b) / max(route_a, 1e-12) < 0.15, "layer missing?"
```

### 规则 7b — 「可提升量」是上界；必须与**已有实现**的实测增益对账

测出"与位置/场点无关、因而可提出循环"的量占比，给出的是**上界**。
若同一件事**已经有实现**（哪怕默认关闭），它的实测增益就是最硬的对照：
两者差一个数量级 ⇒ **必有一处口径有问题**，先查口径，别急着立项。

**真实案例**：实测标量 J 中 r 无关（可提升）的桶合计 **28.5% of build**
⇒ 天花板 1.40×。但已有实现 L2（预算几何 + 逐点复用）记录增益仅 **~3%**。
⇒ 要么 28.5% 在实践中不可兑现，要么 ~3% 的 provenance 有问题；
**结论：该方向应以证据关闭，而不是立项。**

**做法**：给候选方向打分时同时列出
`可提升量上界`、`同类已有实现的实测增益`、`二者的比值`。
比值 > 3 时**先做口径核查**（半日级），再做工程立项（周级）。

## 常见陷阱清单

| 陷阱 | 症状 | 检查 |
|---|---|---|
| 假设代价恒定 | 外推收益偏乐观数倍 | 实测 5–10 点 + 散布 |
| 忽略免费区 | 加速比"名义 N 倍"实为 ~N/2 | 数昂贵区占比 frac |
| 空测试 | Δ=0 被当作 PASS | 断言受控路径非平凡 |
| 小网格固定开销 | 微探针加速比远低于模型 | 分离固定开销：`ovh = t_k − t_1/k` |
| 两个变量同时变 | "加速比"混合了 n_r 与 n_ang | 固定其一 |
| 截断网格与求解网格不一致 | shape mismatch / 结果无意义 | 两处传同一个 grid 变量 |
| 截断半径过短 | 结果数值上"正常"但物理错误 | 确认物理量已充分衰减 |
| 计价模型未对账 | 倍数可信度未知、门槛量纲可能是错的 | 用模型复算冻结锚，要求 <1% |
| 比值分母写错 | 余量/倍数被放大数倍且不报错 | 分母恒等式 `assert` + 产物内 `_field_correction` |
| 粗扫描求极小值 | 判据偏乐观（低估风险） | 量粗/细偏差 → 去偏因子 → 阳性对照 |
| **验收 gate 本身太贵** | 优化可行，但 gate 跑不完/跨轮 | 先给 gate 计价（两臂构建 + 扫描），再决定是否施工 |
| **构成比当贡献比用** | 方向排序错，最高优先项其实只有 1.x× | 报构成比必写例程名；贡献比 = 构成比 × 例程份额 |
| **同名例程多变体** | 在 A 变体上测的分桶被套到 B 变体 | 确认生产热路径调用的是哪一变体（读源码调用点，别看名字） |
| **单层挂钩漏内层同类调用** | 占比低估一个数量级且表面自洽 | 穷举被调函数内部的同类实现；逐层挂钩 + 逐层调用数 > 0 断言 |
| **只报上界不报已有实现** | 立项后收益远低于预期 | 同时列"可提升量上界"与"同类已有实现实测增益"，比值 >3 先查口径 |

## 并行化/开关类优化的专项审计（5 项）

上述三条规则针对"收益核算"。并行化与开关类优化还要多查 5 项——
它们的失效模式不是"加速比不够"，而是**开关看起来生效、实际没生效或生效错了**。

### A. 分派启发式是否覆盖所有生产者分支

**反例（真实案例）**：并行 worker 通过**反射闭包自由变量**判定用哪个求值器：

```python
if   geom_kernels is not None: mode = "l2"
elif bf_cache     is not None: mode = "contracted"
elif mo_coeff     is not None: mode = "reference"
else:                          mode = "zero"        # 兜底 = 静默不算！
```

但 `xalpha`（**默认模式**）分支的闭包自由变量里既无 `mo_coeff` 也无缓存
⇒ 落入 `else` ⇒ worker 直接跳过该势项 ⇒ **物理量静默丢失**（实测偏差 4.46 a.u.，
无异常/无警告）。生产用的 `hf` 路径正常，所以既有测试全绿——缺陷完全潜伏。

**做法**：对每一个"生产者分支"，枚举它构造的闭包/载荷形态，断言分派逻辑
**显式覆盖**它。兜底分支必须**抛异常**，绝不能"静默算零"。

### B. 别信注释里的限制，实测它

**反例**：基准脚本注释断言"Windows spawn 无法 pickle 交换闭包"并据此硬编码
`eff_workers=1`。实测：闭包**从不被 pickle**（设计上已预抽取为 plain-data tuple），
payload round-trip 4.90 MB **成功**，本地 spawn 实测并行有效（1.95×/3.27×，逐位一致）。
⇒ 该硬编码**丢弃了一个可测量的真实结果**，且写进 JSON 的说明文字已是错误陈述。

**做法**：注释里的"不能/不支持"一律当成待验证假设。最小验证 = 对该载荷做
`pickle.dumps`/`loads` round-trip + 实际跑一次小规模并行并计时。

### C. 被测量对象 ≠ 被交付对象（暂存包陈旧）

**反例**：本地已接线（目标符号 10 处），但即将提交的远端 bundle 里**同一文件
覆盖度 = 0**、基准脚本根本不在包内、文件落后 186 行。⇒ 远端会实跑串行，
而本地已生成的 JSON 写着 `l4_plumbed=True` ⇒ **假阳性结论**。

**做法**：提交前 diff 本地与暂存包的关键符号计数；
把"探测结果"（如 `l4_plumbed`）提为**提交前置断言**，而不是事后从本地 JSON 推断。

### D. 枚举"静默降级到串行"的守卫

**反例**：`if n_workers > 1 and _l3_src_idx is None: 并行 else: 串行`——
另一优化（L3）开启时并行被**静默关闭**，无警告。用户请求 8 进程得到 1 进程，
加速比 1.0× 与"该优化无用"无法区分。

**做法**：列出所有把执行引向串行的条件（互斥开关、规模闸门、平台分支），
逐个问"命中时有无诊断"。无诊断的必须在 `else` 加 `warnings.warn`。

### E. 开关是否真的能从顶层入口开启

**反例**：`n_workers` 只存在于一个中层函数及其向下转发（全文 3 处），
顶层物理驱动（`h2_multicentre_xs` 等）**未暴露该参数**。
⇒ 优化无法用于真正的生产计算，只能被基准脚本直接调用。
"端到端墙钟"类问题因此**无法回答**——不是没测，是测不到。

**做法**：从最外层用户入口 `grep` 该开关名，确认可达。
若只在基准脚本可用，明确标注"尚未成为生产可用加速项"。

### 并行化审计的最小证据集

| 证据 | 方法 |
|---|---|
| 并行分支**确实执行** | monkey-patch 计数被调函数（`=2` 时应 1 次、`=1` 时 0 次） |
| 分派覆盖全部生产者分支 | 逐模式跑 `n=1 vs n=N`，以"关掉该开关的构建"为参照判定该势项是否存在 |
| 数值无损 | `max|n=1 − n=N|`，要求 `0.0`（bit-identical）而非仅 `< 1e-12` |
| **真实**加速比 | 实测 `n=1/2/4` 墙钟；对照 Gate `N×eff`，报告并行效率 |
| 载荷可序列化 | 对真实 payload 做 pickle round-trip |
| 交付物与测量物一致 | 暂存包关键符号计数 + 前置断言 |

## 与"声称完成"的区别

本 skill 只用于**核算收益与验证非平凡性**。
给出最终加速比前，必须能回答：
1. 昂贵区占比是多少？**（实测，不是推断）**
2. 受控路径是否被证明非平凡执行？
3. 实测值是否与模型一致？若不一致，固定开销是多少？
